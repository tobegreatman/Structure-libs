# 个股分析框架（stockframe）设计文档

- **版本**：v0.1.0
- **日期**：2026-10-23
- **定位**：中线（6–12 个月）研究复核为主、短线（数周–3 个月）兼顾的个股分析框架
- **读者**：投研人员、量化/数据工程师、复核评审人
- **配套交付物**：`schema/report_schema.json`（输出契约）、`src/stockframe/`（实现）、`examples/`（样例输入/报告）、`docs/02_scoring_guide.md`（评分说明）、`docs/03_acceptance.md`（验收清单）

---

## 1. 定位与边界

### 1.1 目标

1. 对单只个股产出**结构化、可复核、可证伪**的研究报告，核心场景是中线 6–12 个月维度的研究复核（即：检验一份已有研究结论是否仍然成立，或对新标的建立可跟踪的观点档案）。
2. 兼顾短线：短线结论仅作为**参考层**输出，不改变中线定位，避免用短期博弈信号污染中期判断。
3. 所有评分**可拆解到单一指标与量规带**，所有结论**条件化**并附证伪条件，所有数据**可追溯到来源与时点**。

### 1.2 非目标（明确排除）

| 排除项 | 原因 |
|---|---|
| 无条件买卖建议、目标价点位、仓位指令 | 框架输出的是研究分桶（入池/观察/回避/人工复核）与条件化结论，决策权与责任在使用者 |
| 实时行情监控与自动交易 | 跟踪清单给出触发器与确认标准，执行由人/独立监控系统完成 |
| 替代实地尽调、专家访谈 | 数据面框架，定性输入由分析师按锚定量表录入并留痕 |
| 财报预测模型（自动编表） | 情景假设显式标注为 assumption，与数据严格隔离 |

### 1.3 合规底线

- 报告尾部固定输出免责声明（见 schema `disclaimer` 字段，固定文案，禁止改写）。
- 框架**不接接任何"荐股"语义**；分桶名称与文案均不包含"买入/卖出/加仓/减仓"等操作词。

## 2. 设计原则（反黑箱五原则）

| # | 原则 | 落地机制 |
|---|---|---|
| P1 | **可拆解** | 评分层级：维度 → 因子 → 指标 → 量规带。任何分数都能逐层回放为 `原始值 → 命中量规带 → 得分 → 加权聚合`（见 §5） |
| P2 | **可追溯** | 每个输入字段携带 `{value, as_of, available_at, source, source_tier}`；报告附 evidence_log（见 §4.2、§4.6） |
| P3 | **时点纪律** | 三时点模型 + PIT 校验器，任何 `available_at > analysis_date` 的数据触发 `LookAheadError` 拒绝入模（见 §4.4） |
| P4 | **条件化** | 结论必须形如"若 X 且 Y 成立，则维持 Z"；附证伪条件（带阈值与观察指标）与有效期（见 §12） |
| P5 | **少而精** | 指标准入三问：有无方法论依据？阈值能否显式锚定？缺失时能否识别而非伪装？不满足则不收录。硬性上限：每维度因子数 ≤3、每因子指标数 ≤4，且每个指标必须携带 rationale（由测试强制，见 tests/test_scoring.py） |

**黑箱判定红线**（验收必查）：存在任何"输入数字、输出分数、中间不可见"的路径即为黑箱；存在"为凑数而收录、无阈值锚定"的指标即为堆砌。

## 4. 数据字典与时点规范

### 4.1 三时点模型（反未来函数的核心）

| 时点 | 含义 | 示例 |
|---|---|---|
| `period_end` | 数据所属报告期/统计截止 | 2026-06-30（中报期末） |
| `available_at` | 数据**实际可得**时点（披露日/发布日/交易日） | 2026-08-28（中报披露日） |
| `as_of` | 数据取值基准时点 | 2026-06-30 的 ROE，as_of=2026-06-30 |

**规则**：
1. 分析时点 `analysis_date` 下，只允许使用 `available_at ≤ analysis_date` 的数据。
2. **报告期 ≠ 可得时点**：Q2 期末 6-30 的财报，8 月底才可得。用 `period_end` 做可用性判断就是未来函数。
3. 价格类数据 `available_at = as_of = 交易日`，且必须 `≤ analysis_date`；`analysis_date` 当日盘中数据不用于收盘口径计算。
4. 历史分位类指标（如 PE 10 年分位）必须声明计算窗口 `[window_start, window_end]`，且 `window_end ≤ analysis_date`。

### 4.2 来源分级

| 等级 | 来源类型 | 采信规则 |
|---|---|---|
| L1 一手 | 交易所公告、公司财报、统计局、央行/监管 | 直接采信，标注机构+发布日期 |
| L2 结构化二次 | 官方数据服务（行情/财务数据库） | 采信但需标注库名+时点 |
| L3 研报/第三方研究 | 券商研报、行业报告 | 采信需标注机构+时间，标注"需核实原文" |
| L4 媒体/传闻 | 财经媒体、市场消息 | 只作线索，不得进入评分计算（可进催化剂日历并标注未证实） |

DQ 与置信度随来源等级降级（§5.5、§6）。**L4 来源进入评分路径属于硬错误。**

### 4.2b 输入契约（`pit.py` + `contract.py`，违反即报错）

时点纪律守的是"用没用未来的数据"，契约守的是"数据本身是不是数据"。评分带用 `v >= lo and v < hi` 比较，于是：

| 脏输入 | 旧行为（安静地错） | 现在 |
|---|---|---|
| `NaN` | 对任何比较都 False → 落进**最差档**，当真实分数，置信度不变 | `ContractError` |
| `+Inf` / `-Inf` | 命中末带 → 落进**满分档**，仍可入池 | `ContractError` |
| 档位 `4.7` | `int()` 截成 4 → 整个因子偏 2.5 分 | `ContractError`（必须整数 1–5） |
| 档位 `9` | 静默当缺失 → 整块判断消失 | `ContractError`（越界） |
| 文本字段填 `12345` | 原样拼进结论首句 | `ContractError`（必须字符串，≤200 字） |
| 字段名拼错（`roe_typo`） | 该字段静默消失，指标按缺失、分数照常输出 | `ContractError` 且提示相近字段 |
| `price ≤ 0` | 安全边际变 `inf` 或符号反转 | `ContractError`（必须为正） |
| 空白字符串 | 被当作已提供，顶掉"未填"提示 | 归一为缺失，DQ 记缺口 |

一台"可追溯的记账机"最怕的不是算错，是**输入错了还算得很顺**：报告照样通过 schema、照样出分桶，只是每个数字都站在 NaN 上。契约把这类失败提前到入口。

### 4.3 字段字典（核心字段，实现于 `datadict.py`，代码即文档）

结构：`<组>.<字段>`，每组输入形如：

```json
{
  "field_id": {"value": 12.3, "as_of": "2026-06-30", "available_at": "2026-08-28",
               "source": "公司2026年中报", "source_tier": "L1", "unit": "%"}
}
```

| 组 | 核心字段（value 单位） | 更新频率 | 典型可得滞后 | 典型来源等级 |
|---|---|---|---|---|
| market | price_close(元), pe_ttm(×), pb(×), pctile_pe_10y(%), pctile_pb_10y(%), turnover_pct(%), vol_ratio_20d(×), dist_ma250(%), drawdown_52w(%), inst_hold_chg_pct(pp) | 日 | T 日收盘后即得 | L2 |
| macro | m1_yoy(%), rate_10y_chg_yoy(bp), pmi(点), policy_stance(1–5 定性) | 月 | 发布日 | L1 |
| industry | industry_growth(%), price_trend(1–5 档，对应 -2..+2), stage(1–5), concentration(1–5), penetration_space(1–5) | 季 | 研究更新日 | L2/L3 |
| company | moat(1–5), mgmt_record(1–5), pledge_pct(%), logic_strength(1–5), logic_essence(文本), customer_concentration(%)（**年报**）, logic_items[](结构化逻辑) | 事件/季/年 | 公告日 | L1/L3 |
| financial | roe_ttm(%), roic(%), wacc_assumed(%), ocf_np_ratio(×), wc_growth_gap(pp), rev_growth(%), np_growth(%), gm_trend(pp), int_debt_ratio(%), goodwill_pct(%), red_flags[] | 季 | 披露日 | L1 |
| valuation | eps_ttm(元)（**季**，分子来自定期报告）, peer_pe_median(×), pe_hist_p25(×), pe_hist_p75(×), eps_fwd(assumption), dcf_inputs{} | 日/季 | — | L2 + assumption |
| catalysts | events[]{date, type, direction, strength, priced_in, verify_method} | 事件 | 公告日 | L1/L4 |
| risk | risks[]{probability 1–5, impact 1–5, trigger, category} | 事件/季 | — | L1/L3 |

**预测数据隔离**：`eps_fwd_list`、DCF 假设、情景概率一律带 `"kind": "assumption"`，在报告中原样标注，不得与 data 混排。

### 4.4 PIT 校验规则

1. 引擎启动时遍历全部输入字段：`available_at > analysis_date` → `LookAheadError`（异常含字段名与两个时点，直接终止）。
2. 价格 `as_of > analysis_date` 同样拒绝。
3. 催化剂日历中的**未来事件**是合法的（事件尚未发生，不是未来数据），但必须 `date ≥ analysis_date`，已发生事件只允许出现在"已定价"证据里。
4. **来源等级校验**：`source_tier = L4`（媒体/传闻）的字段一律抛 `ProvenanceError`——L4 只能作为催化剂线索，不得进入评分路径。
5. 定性评分（如 moat 1–5）的 `available_at` = 评估形成日，同样受 PIT 约束。

### 4.5 缺失数据处理（不静默补零）

- 指标缺失 → 该指标 `score=null`，因子层按可用指标权重**重归一化**计算，并在报告中标 `"未评分"`。
- 必填字段（见 schema `required`）缺失 → 不进入分桶，直接路由 **人工复核**，理由写明缺失字段清单。
- 重归一化比例 < 60%（因子内可用权重占比）→ 该因子置信度降一档。
- **上界不是点估计，但也不该丢**：有些字段拿不到点值，却拿得到一个可靠的**上界**
  （典型是"最大客户收入占比"：年报常只披露前五名合计）。规则是——值继续留空、不参与评分，
  但把上界、上界对应的**最坏档位**和它的证据来源一起写进缺口说明与评分卡指标行。
  理由有两条：① 留空而不说，读者会去翻一份翻不出结果的年报；② 说清楚"最坏也只到这一档"，
  才能判断这个缺口值不值得补。**边界**：上界只能用来界定"最坏是什么"，永远不许当值参与加权
  （把 48.11% 当成"最大一家"会把它判成"中"档，而真实值可能是 12%）。

### 4.7 披露节奏 ≠ 统计口径（两把尺子）

一份报告里同时存在两种"新"：

- **最新报告期**：最近一期已公告的定期报告（多数时候是季报）。TTM、ROE、增速这些**累计口径**跟着它走。
- **最近一期年报**：只在年报里披露的东西（目前唯一一项是"最大客户收入占比"）。它一年只披露一次，
  滞后 0~15 个月都属正常。

两者不能混，否则会得出反直觉的结论。举个真实的例子（2026-10-23 分析 300750）：
最新报告期是 `2026-09-30`（三季报），最近一期年报是 `2025-12-31`（2026-03-10 公告）。
如果拿"季频 92 天"去卡客户集中度，那么

- 2026-04~07：新鲜；
- 2026-08 之后：判"超期 2 倍"，降及时性评分；
- 而它的下一个可用值要等到 2027-03 的年报。

于是这个字段**一年里只有三个月算"新鲜"**——看起来像"数据取不到"，其实是尺子用错了。
同一个坑还有 `valuation.eps_ttm`：分子来自定期报告，原先标成日频（1 天），
季报公布两个月就被判"超期 2 倍"，而它明明是最新的。

**实现约束（`datadict.py` → `autobuild.py` → `dataquality.py`）**：

| 环节 | 规则 |
|---|---|
| 字段登记 | `FieldSpec.annual=True` 的字段，`update_days` 必须 ≥ 365；定期报告口径的字段 ≥ 90；只有行情类才是 1 |
| 取数输出 | `fill.as_of` 同时给 `latest_report_period` / `latest_report_notice` 与 `latest_annual_period` / `latest_annual_notice`；`fill.annual_fields` 列出年报口径字段 |
| 自动取数 | 年报口径字段只能从**已公告的年报原文**里取（见 §18.8）：`as_of` = 该年报期末，`available_at` = 该年报公告日；公告日晚于分析时点的一律不用 |
| 人工手填 | 年报口径字段的数据期 `as_of` = 最近一期年报**期末**，`available_at` = 该年报**公告日**（不是录入当日） |
| 数据质量 | 备注里注明"只在年报披露的字段，数据期为最近一期年报、不随季报前移"，且不参与"超期"判定 |
| 告警 | "非完整年度"的提示里必须点明：累计口径按跨年拼接/年化，年报口径字段取哪一期、滞后一年内属正常 |

**为什么 `available_at` 不能记成录入当日**：那样一年前的数字会被显示成"今天刚拿到"，
及时性评分虚高，读者也失去判断数据陈旧度的依据。录入手填这个动作发生在今天，
但这条**信息**在年报公告日就已经可获得——PIT 记录的是后者。

**反过来也成立**：`as_of` 也不能记成分析日。否则"2025 年报的数"会被当成"2026 年三季度的数"，
跨期比较（比如与营收增速比、与同业比）就会出现口径错位。

### 4.6 证据日志（evidence_log）

报告尾部汇总：`{field_id, source, source_tier, as_of, available_at, used_by[指标id]}`。任何一个分数都能反查它用了哪些字段、来自哪里、什么时点。

## 5. 评分体系

### 5.1 层级与记法

```
维度得分 = Σ(因子得分 × 因子权重)
因子得分 = Σ(指标得分 × 指标权重)     # 按可用权重重归一化
指标得分 = 量规带(原始值) → 带内定值 ∈ {0..10}，带具名
```

- 全部量规为**阶梯带**（非连续函数）：显式、可复核、无隐藏形状。
- 每个量规带带 `label`（差/弱/中/良/优），每条阈值在评分说明中给**锚定依据**（方法论出处或行业常识区间），拿不出依据的指标不许进 specs。
- 定性指标（moat、治理、行业阶段等）用 **1–5 锚定量表**（每档写行为描述），分析师只能选档，不能自由填分——档位描述进报告。

### 5.2 双周期权重（默认值，可配置覆盖）

| 维度 | 中线权重 | 短线权重 | 设计依据 |
|---|---|---|---|
| 宏观 | 0.08 | 0.05 | 中线受宏观传导影响但非主矛盾；短线仅影响风险偏好 |
| 行业 | 0.14 | 0.10 | 景气与格局决定中期盈利方向 |
| 公司 | 0.22 | 0.05 | 护城河/治理/逻辑是中线定价核心 |
| 财务 | 0.20 | 0.05 | 质量→增长匹配决定中线持续性 |
| 估值 | 0.16 | 0.05 | 中线赚业绩钱+估值钱，安全边际重要 |
| 催化剂 | 0.06 | 0.30 | 短线核心是事件与预期差 |
| 交易面 | 0.06 | 0.30 | 短线由趋势/量价/拥挤度主导 |
| 风险 | 0.08 | 0.10 | 双向计入，短线略高（回撤快） |

中线公司+财务+估值 = 58%，体现"基本面为主、择时为辅"；短线催化+交易面 = 60%，体现"事件与筹码为主"。两组合计均为 1.0。

### 5.3 八维度因子结构（摘要，完整量规见评分说明）

| 维度 | 因子(权重) | 指标（每因子 ≤4，示例） |
|---|---|---|
| 宏观 | 流动性利率(0.5)、增长政策(0.5) | M1 同比趋势、10Y 利率同比变化、PMI、政策取向(1–5) |
| 行业 | 景气(0.4)、格局(0.35)、空间(0.25) | 行业增速、量价趋势、行业阶段(1–5)、集中度/份额(1–5)、渗透空间(1–5) |
| 公司 | 护城河(0.5)、治理(0.3)、逻辑强度(0.2) | moat(1–5 锚定)、管理层记录(1–5)、质押比例、逻辑预期差(1–5，按 logic_items 结构化) |
| 财务 | 盈利质量(0.4)、增长质量(0.35)、资本回报(0.25) | ROE_TTM、OCF/净利、WC 增速差、营收/净利增速、毛利趋势、ROIC−WACC 差、有息负债率、商誉占比 |
| 估值 | 绝对安全边际(0.45)、相对位置(0.35)、预期匹配(0.2) | DCF 中枢/现价比、PE 10 年分位、PB 10 年分位、PEG |
| 催化剂 | 中线密度(0.5)、短线强度(0.5) | 6–12 月催化数量×级别、下一事件强度、已定价程度 |
| 交易面 | 趋势位置(0.4)、量价筹码(0.35)、拥挤度(0.25) | 距 250 日线、距 52 周高点回撤、20 日量比、换手分位、机构持仓变化 |
| 风险 | 可控度(1.0) | 风险矩阵加权分、财务红旗数、客户/供应商集中度 |

### 5.4 量规带示例（ROE_TTM，完整表见评分说明）

| 带 | 阈值 | 得分 | 依据 |
|---|---|---|---|
| 优 | ≥18% | 10 | 消费/制造龙头长期 ROE>20% 为优秀（质量方法论），18 为放宽门槛 |
| 良 | 12–18% | 7.5 | — |
| 中 | 8–12% | 5 | — |
| 弱 | 4–8% | 2.5 | — |
| 差 | <4% | 0 | — |

### 5.5 置信度模型

每个维度独立置信度 `conf_d ∈ [0,1]`：

```
conf_d = 1.0
       − 0.06 × 缺失指标数                        (完整性惩罚)
       − 来源惩罚：L1:0 / L2:0.02 / L3:0.08 / L4:禁止入模
       − 时效惩罚：数据年龄 > 1.5×更新周期 → 0.1；> 2× → 0.2
       − 因子重归一化 < 60% 的因子 → 0.05/个
       下限 0.2，上限 1.0
```

综合置信度 = Σ(conf_d × 周期权重)，再乘 DQ 总分（§6）。映射：≥0.75 高 / ≥0.5 中 / <0.5 低。

## 7. 估值模块（两种方法）

### 7.0 适用性前门（先判断该不该算，再谈算多少）

估值的第一道不是公式，是**方法成不成立**。前门由 `meta.company_type` 决定（注册表见 `datadict.COMPANY_PROFILES`）：

| 类型 | DCF | 可用口径 | 理由 |
|---|---|---|---|
| high_growth / steady_growth / value / platform / cyclical / resource | 适用 | PE（仅 PE 已实现） | 营收×EBIT率路径是主要价值来源 |
| financial / bank / insurance / reit | **不适用** | PB | 价值来自资产负债表（息差、准备金、资本化率），净债务与资本开支口径不成立 |
| loss_making（EPS≤0 或 PE≤0 自动升级） | **不适用** | PS | PE 无意义；EBIT 率为负会让显性期现金流为负、区间可输出负股价 |
| pre_revenue | **不适用** | PS | 营收与利润率假设无锚，DCF 只是把假设放大 |

不适用时：`valuation.dcf.applicable=false` 且**不含任何 DCF 数字**，`synthesis.mode=not_applicable`、`combined_range` 与 `safety_margin_pct` 全为 `null`、`scenarios=[]`，决策落 `R9_MODEL_NOT_APPLICABLE` → 人工复核。

这不是"降级"。降级仍会印一个数，读者只会记住那个数——平安银行曾被算出 24.58–33.28 元、对股价 11.20 的安全边际 +95.7%，唯一拦住它的是覆盖闸门而不是行业判断。

**口径必须与类型自洽**：`bank` + `PE` 直接报错，不静默换算法。自动取数按申万二级行业名判定类型（银行/保险/证券/地产），判不了则按增速推断，并在 `fill.warnings` 里明说"未做行业分类"。

### 7.1 方法一：FCFF DCF（绝对估值）

- 5 年显性期 + 永续（Gordon）。`WACC` 输入区间默认 8%–12%，`g` 默认 2%–3%（超 GDP 增速报警）。
- 三情景假设（乐观/基准/悲观）各自驱动收入增速、利润率、资本开支路径；**永续 TV 占比 >70% 触发警示**（终值主导，结论可信度降档）。
- 输出：每股内在价值 ×3 情景 + 基准情景 `WACC×g` 敏感性网格（5×5）——敏感性矩阵本身就是反黑箱交付。
- DCF 输入全部标注 `kind=assumption`。

### 7.2 方法二：相对估值（分位带）

- **已实现的口径只有 PE**：分位带 × EPS(TTM) 折算隐含价位。PB/PS/EV-EBITDA 缺"每股净资产/每股收入"字段，`relative_metric.supported=false`，该法按不可用处理（`available=false`、区间 null），**不拿 PE 的算法冒充 PB 的结果**。
- 历史 10 年分位带：<30% 偏低、30–70% 中性、>70% 偏高（估值方法论阈值）。
- 隐含价格区间 = [历史 P25, P75] × EPS（TTM 与基准 fwd 各算一条），同业 PE 中位数作为交叉锚。
- **同业锚只在可比时折算价位**：本公司估值 / 同业中位落在 0.5–2 倍之外，业务结构差异足以解释倍数差，此时 `peer_anchor.implied_price=null`，只报溢价/折价百分比（见 §18.7）。
- 必须输出"当前估值已定价了什么"（结合情景假设与预期差）。
- **不可用即声明**：`PE(TTM)` 或 `EPS(TTM)` 缺失、**或 PE≤0 / EPS≤0（亏损）**时输出 `available=false`、区间为 `null` 并写明原因，**不外推、不用 ±20% 兜底伪装成结论**。亏损时负 EPS 乘出来的价位是负股价，这类区间一律拒答。

### 7.3 区间合成（不给单点价格预测）

- 双法区间并列呈现；**合成区间** = 基准情景 DCF 区间与相对法区间的交集（若空则取并集并降置信度一档、注明分歧）。
- 相对法不可用时，`mode=dcf_only`，合成退化为 DCF 单法区间且置信度置 `low`（单法无法交叉验证）。
- 合成仅用于"安全边际"指标评分与情景锚，**报告正文禁止出现单一价格点位预测**。

## 8. 情景分析（乐观/基准/悲观）

每个情景结构固定：

```
{name, probability(三情景合计=1), key_assumptions[](可勾稽到 DCF/相对法输入),
 value_per_share_range, drivers[], 与基准差异摘要,
 falsification(该情景失效条件), evidence_refs[]}
```

- 概率默认 乐观 0.25 / 基准 0.50 / 悲观 0.25，允许覆盖但**强制合计=1**（schema 校验）。
- 期望值 = Σ(情景中枢 × 概率)，仅作参考量，附"期望值非目标价"标注。

## 9. 风险矩阵

- 每条风险：`{id, name, category, probability 1–5, impact 1–5, trigger(触发器/可观察指标), mitigation, evidence}`。
- 风险值 = P×I ∈ [1,25]；级别：≥16 高 / ≥9 中 / <9 低。
- 输出 5×5 网格计数 + Top 风险（按 P×I 排序前 5）。
- 矩阵同时喂给：风险维度评分（§5.3）、跟踪清单（§13）。

## 10. 催化剂日历

每条：`{date/window, event, type, direction(+/-), strength(强/中/弱/噪音), expected_impact, priced_in(未定价/部分定价/已定价), verify_method}`。

- 强度判定按催化方法论（真实性、新颖度、可理解性、可外溢性、可跟踪性五问）。
- **已定价的利好是兑现风险**——`priced_in=已定价` 且 `direction=+` 的事件在报告中标警示。

## 11. 决策映射（评分 → 四桶）

**输出语义**（唯一合法出口）：

| 桶 | 语义 |
|---|---|
| 入池 | 通过全部硬门槛且中线综合分达阈，进入研究池做进一步工作 |
| 观察 | 核心逻辑存在但验证不足/数据待补，列入跟踪清单等待条件 |
| 回避 | 硬红旗或中线综合分过低，不投入研究资源 |
| 人工复核 | 数据质量/信号冲突/特殊情况导致框架不能可靠出桶，转人工 |

**判定顺序（先于分数）**：

1. **硬红旗 → 回避**：ST/*ST、审计非标意见、监管立案、财务造假红旗（**红旗数 ≥2 条亦直接回避**，红旗影响呈陡峭边际）。
2. **强制人工复核**：
   - DQ < 0.5 或必填字段缺失；
   - **估值方法不适用**：`company_type ∈ {financial, bank, insurance, reit, loss_making, pre_revenue}`（含 EPS≤0/PE≤0 自动升级）时，本框架没有该类的估值口径，综合分只在已覆盖维度上重归一化，不能当分桶依据（规则 `R9_MODEL_NOT_APPLICABLE`，见 §7.0）；
   - **研究判断层证据不足**：`判断层覆盖 = Σ(宏观/行业/公司 维度权重 × 该维度可用指标权重占比) ÷ Σ(三层维度权重)`，低于 **0.60** 时不出正式分桶（规则 `R7_COVERAGE`）。综合分只在有数据的维度上重归一化，若不设闸门，"只填了财务+行情"的标的也能拿到 6–7 分并被判观察，读者会误以为宏观/行业/公司三层已被评估过。**分母只含这三层**：财务/行情/估值永远可得，计入分母会稀释信号（详见 §18.5）；
   - **数据层覆盖不足**：财务/估值/交易三个维度各自的指标级覆盖 < **0.60** 时同样不出正式分桶（规则 `R8_DATA_COVERAGE`）。覆盖闸门原先只管判断层，结果是把财务删到只剩 ROE+营收增速仍 7.57 入池、交易面全删仍 7.52 入池——数据缺口只降置信度、不改桶；
   - **信号冲突**：仅当 `中线综合 ≥7.0`（本应入池）而任一单维 `≤3.0`——"贵的优质 / 便宜的质量陷阱 / 基本面与风险画像冲突"属判断分歧点，机器不独断；
   - 特殊状态：停牌、重组进行中、上市 <1 年。
   > 冲突检测的**前置条件是主信号成立**：综合分未达入池线时结果本就是"观察"，不再升级为人工复核（避免稀释复核资源）。
3. **分数分桶（中线综合分，0–10）**：`≥7.0 入池`（且无维度 <4.0）；`5.0–7.0 观察`；`<3.5 回避`；`3.5–5.0 观察（偏谨慎）`。
4. 短线综合分仅输出参考桶（同阈值），标注"短线参考，不改变中线定位"。

**规则编号可溯源**：报告输出 `decision.rule_id`（R1 硬红旗 / R2 红旗≥2 / R3 DQ 强制 / R4 特殊状态 / R5 信号冲突 / R6 分数分桶 / R7 判断层覆盖不足 / R8 数据层覆盖不足 / R9 估值方法不适用），审阅人不必从一段摘要里猜结论怎么来的。

**禁止**：任何桶附带价位、仓位、买卖时点建议。

### 11.1 结论翻转点（sensitivity）

分桶只是结论的一半，另一半是"这个结论有多经得起单维恶化"。报告因此附一份 `conclusion.sensitivity`：
把某一维度**单独**下调，二分求出分桶第一次改变的最小位移（`delta`），并按位移升序排列。

三条机制全部来自上面的判定顺序，不新增规则：

| mechanism | 触发条件 | 为什么常常它最先 | 样例 |
|---|---|---|---|
| `dim_floor` | 综合分仍 ≥7.0，但该维跌破 **4.0** | 入池要求"无维度 <4.0"，低权重维度掉到 4.0 只需几小分，掉 10 分却不可能 | 估值 6.12 → −2.13 |
| `score_band` | 综合分跌破分界线（入池 7.0 / 观察 3.5） | 高权重维度（公司 0.22）每掉 1 分，综合分掉 0.22 | 公司 7.5 → −2.92 |
| `signal_conflict` | 综合分 ≥7.0 且估值/风险/财务 ≤3.0（R5） | 实际上**永远不会最先**：任何 ≤3.0 必先跌破 4.0（见下） | — |

两条必须写进文档的推论：

1. **5.0 不是翻转线**。观察桶里跌破 5.0 仍是观察，真正的翻转线是 3.5 —— 对外报"距 5.0 还有多远"会让人误以为跌破就换桶。
2. **R5 晚于维度下限**。"某维 ≤3.0 → 人工复核"要求综合分 ≥7.0，而任何 ≤3.0 的维度必然先跌破 4.0 的入池下限（4.0 > 3.0）。所以 drivers 里只会出现前两种机制；R5 分支保留是为了让机制名与规则表一一对应，将来若调下限，判定自动跟随。

边界与纪律：只算**分数驱动**的机制。R1–R4、R7–R9 由输入与覆盖决定，当前桶若已是回避/人工复核，则不出位移（`drivers=[]` 并给出原因），不假装能算。这是一条"对结论本身的预测"——算术恒等、可复算，**不涉及任何价格方向**；它不能替代回测（D4），也不构成"这套分数能预测收益"的证据。

### 11.2 方向上还缺的一半：桶内位置与向上档位

只报"距 7.0 线 +0.64 分"有两处读不通：0.64 分是宽是窄没有尺度；而且人默认上面还有空间。
所以在 `sensitivity` 里再给四组字段，全部是同一批数的除法，不引入新判定：

| 字段 | 回答什么 | 样例 |
|---|---|---|
| `band.position` / `band.zone` | 分数在本桶区间里走到哪（0=刚够格，1=触顶），三等分给"下沿/中段/上沿" | 7.64 → 21%，下沿 |
| `headroom.at_top` | 本桶是不是最高档。**入池之上没有更优档**，此时 `room=null` | `true` |
| `headroom.room` / `next_up` | 观察/回避桶往上还差多少分、进哪个桶 | 观察 6.0 → 差 1.00 分进【入池】 |
| `distance_anchors` | `distance` 折成档（每档 2.5 分），0.26 档读作"不足一档" | 0.26 |

两条纪律：

- **`zone` 的三等分是纯位置描述，不是对标的的评价**。分界刻意等分——任何"更聪明的"切点都需要依据，而这里没有依据可取。
- **"方向"指结论档位的方向，不是股价方向**。`at_top=true` 的正确读法是"这个结论已到顶，能变的只有往下"，
  不是"股价见顶"。界面上这一句必须带"档位"二字，否则会被读成价格判断。

### 11.3 立场句（stance）：把分桶翻成"现在该不该动手"

分桶名对非专业读者不构成答案。实测把分数结构、翻转点、维度排序、两法分歧四行摆在一起，
读者的反馈是"看完还是不知道该不该买"。于是 `conclusion.stance` 给一句明确的话：

| 桶 | code | label | 这句话在答什么 |
|---|---|---|---|
| 观察 | `hold_off` | 暂不介入 | 差多少分进候选池；**话要说透：继续看着 ≠ 可以动手** |
| 入池 | `research` | 够格研究 | 够格进候选池；**入池 ≠ 现在买**，它给的是研究顺序 |
| 回避 | `avoid` | 按框架规避 | 跌破 3.5；这不是"便宜"，是"质量不够" |
| 人工复核 | `insufficient` | 本框架不下结论 | 不是"不好"，是"这套尺子量不出来"，并点明哪条闸门 |

字段是 `code/label/headline/basis/do_next[]/abandon/caveat`，三条纪律：

1. **不新增判定**。`code` 只由 `bucket_mid` 决定，四对四，不出现第五种。立场句放在引擎而不是前端，
   因为它是结论的一部分——前端各拼一句，同一份报告在不同视图里就会说不同的话（§16.1）。
2. **它必须过 A4 词表**。这是全文最像投资建议的一段，反而最需要闸门（`wording.enforce_report`
   已把 stance 全部字段纳入扫描）。
3. **它必须诚实**。`caveat` 写死一件事：本框架没有回测样本，算不出涨跌概率，所以不出现买卖措辞，
   只回答"够不够格"。不把这层说透，读者只会觉得系统在打太极。

还有一条只能写在 `do_next` 里、但很关键的话：**分数不会因为股价下跌自己变高**——
它衡量的是公司质量与估值，不是涨跌空间。"等它跌下来再买"是对这套分数最常见的误读。

## 12. 条件化结论与证伪条件（模板）

```
结论: <bucket>（中线置信度 <高/中/低 0.xx>；短线参考 <bucket>）
维持条件（全部成立才维持当前桶）:
  C1: <可观察条件 + 阈值 + 数据源>
  C2: ...
证伪条件（任一触发 → 立即重估，非降档处理）:
  F1: <指标跌破/超过阈值> → <影响哪个维度哪个逻辑>
  F2: ...
有效期: analysis_date + 90 天（中线季度复核；短线事件驱动即时复核）
```

证伪条件生成源：投资逻辑的预期差失效点、风险矩阵高等级风险的 trigger、情景分歧变量、估值合成区间的下沿。

## 13. 跟踪清单

生成规则（每条）：`{item, metric, threshold, direction, cadence, action_on_trigger, source}`

1. 全部证伪条件 → 监控项（cadence=事件/日/周按指标频率）；
2. 高/中风险 trigger → 监控项；
3. 催化剂日历 verify_method → 到期核验项；
4. 关键财务比率的下季披露核验（对齐 PIT：下期 available_at 之后才能评价）。

输出契约 = `schema/report_schema.json`（Draft-07）。顶层：

```

catalyst_calendar / tracking_checklist / data_quality / evidence_log / disclaimer
```

## 16. 交互界面（Web 控制台）

### 16.1 定位：薄壳，不复制逻辑

界面不是第二套实现。`server.py` 只做三件事：路由、调 `engine.run()`、把异常翻译成可读的 4xx。
评分、估值、决策全部复用同一份 Python 代码，因此"界面上的分数"恒等于"CLI 算出的分数"。
这条约束由验收 A14 钉住：同一份输入，比对接口结果与引擎直算结果的分桶与综合分。

### 16.2 启动方式

```bash
PYTHONPATH=src python -m stockframe.server --open     # 默认 127.0.0.1:8770
```

- 只绑定回环地址（传其它 host 会打印告警）；请求体上限 8MB；服务端不落盘、无状态。
- 也可直接双击 `web/index.html`：进入**离线快照模式**，展示随构建内联的样例报告（只读），
  并提供启动本地引擎的提示——保证"没有任何环境也能看懂交付物长什么样"，但不会假装能重算。

接口：`GET /api/health` · `GET /api/meta`（数据字典）· `GET /api/sample` · `POST /api/analyze`。

### 16.3 页面结构（10 个视图）

### 16.4 交互约束（与方法的对应关系）

- **结论可解释**：标题条直接显示 `decision.rule_id`（R1–R6）与分桶理由，界面与报告同源，不存在"界面说得更漂亮"。
- **错误不吞**：输入面板把 `LookAheadError` / `ProvenanceError` 的原始消息回显（字段级），用户能立刻定位是哪个字段的 `available_at` 越界。
- **不越界**：界面文案同样受 A4 约束，不出现买卖/点位措辞；导出仅有 JSON（报告）与 Markdown（研究底稿）。
- **可分享**：`#scorecard`、`#risks` 等哈希深链直达视图，便于复核时定位。
- **离线可用**：图表为内联 SVG / CSS，字体用系统字体栈，无 CDN、无第三方脚本。
- **可读性有硬指标**：四级文字色在白底与页面底均满足 WCAG AA（≥4.5:1，实测 muted 6.7、faint 5.2）；
  `--ghost` 只用于纯装饰（折叠箭头、矩阵空位），不承载任何信息——旧版 `--faint` 只有 2.6:1，
  却承担了 35 处指标/权重的显示，是这套界面唯一的合规缺陷。
- **结论条不做长句拼接**：`一句话本质` 独占两行，其余事实（规则·归因·覆盖·估值口径·缺口）降为 chip；
  摘要里不再出现"主要归因 = 数据质量备注第一条"这类只取数组首项的做法——有缺口先报缺口，无缺口才报权重归属。
- **版式由变量收放**：内容栏宽度与两侧留白只定义一次——`:root` 的 `--shell`（1420px）/ `--gutter`（22px），
  顶栏、结论条、标签页、主体、抓取条、提示条六处共用 `var(--shell)` + `var(--gutter)`，不再各自写死 `max-width:1420px`。
  窄屏（≤760px）把 `--gutter` 收到 14px 并让操作按钮换行。断点（1080 / 760）表达的是布局语义而非长度，
  仍是常量——`var()` 不能用于媒体查询条件，这是有意的取舍。
- **有"研判"，没有"建议"**：概览右栏的四行（定位 / 翻转 / 触发 / 边界）是这套界面唯一接近"观点"的地方，
  但每一行都是引擎字段的直译——`sensitivity`（翻转点）、`decision`（规则与理由）、`falsification`（证伪阈值）、
  `score_attribution` + `synthesis`（边界说明）。前端只决定"先说哪一句"，不决定"结论是什么"。
  它刻意不产出目标价、涨跌概率、评级、仓位——那四类在本框架里没有证据（0 行回测），
  且前两类会被 A4 措辞闸门直接拦下；绕到前端硬写虽然拦不住，但那是绕过自己的出口检查。

### 16.5 防"界面漂移"

`web/index.html` 由 `web/app.template.html` + `examples/sample_report.json` 构建生成（`tools/build_ui.py`）。
内联快照是为了 file:// 下绕开浏览器对本地 JSON 的跨域限制。A13 用 `--check` 做字节级比对：
样例报告更新后若忘记重建界面，验收直接失败——与 A11（文档漂移）同一思路。

## 17. 自动取数（按代码/名称一键分析）

### 17.1 为什么要有这一层，以及它的边界

手工填 39 个字段不现实，但"一键出结论"又会退化成黑箱。因此自动取数只做**可机读的事实与可复算的代理**，
把**真正只能由人判断的东西明确留空**（判断项的代理口径见 §18）：

| 自动填充（35 个字段） | 必须人工补（4 个字段） |
|---|---|
| 行情：收盘价、PE/PB、十年分位、均线偏离、回撤、换手率、20 日量比、机构持仓变化 | 宏观：政策取向 |
| 财务：ROE(TTM)、ROIC、营收/净利增速、现金含量、毛利率趋势、有息负债率、商誉占比、应收+存货增速差 | 行业：渗透空间 |
| 估值：EPS(TTM)、PE 历史 P25/P75、同业 PE 中位数 | 公司：投资逻辑强度、一句话本质 |
| **年报原文**：客户集中度（巨潮年报 PDF，L1，见 §18.8） | — |
| **判断代理**：M1、PMI、10Y 国债收益率同比、行业增速/量价/阶段/卡位、护城河、管理层记录、质押 | — |
| 假设：DCF 三情景参数（**机械外推**，见 §17.4） | — |

> 总市值不写入字段：它不进任何评分/估值口径（DCF 用股本×价格），写进去只会让"已填 N/39"对不上账。


自动模式跑出来的典型结果是 **`观察 / R6_SCORE_BAND`**（判断层覆盖 ~81%）；判断层证据不足时仍会落到
`人工复核 / R7_COVERAGE`（如平安银行 52%——银行毛利率不可比，护城河代理失效）。
这说明闸门仍然在起作用，只是不再一律拦死。

### 17.2 架构：seam 划在网络 I/O 与纯计算之间

```
sources/eastmoney.py   取数 + 归一化 → RawStock（可 JSON 序列化，能落 fixture）
sources/chinabond.py   10Y 国债收益率（日频）+ 一年前锚点对齐，PIT 按次日可用
        ↓
autobuild.py           PIT 过滤 → TTM 推导 → 分位计算 → 机械假设 → 风险/催化最小集
        ↓
engine.run()           与手工输入走完全相同的评分/估值/决策管线（零特例）
```

取数依赖网络、几乎无法离线测；而时点与口径推导是正确性核心，必须能手写 fixture 反复回归。
因此数据源只负责 HTTP 与字段映射，一切"算"都在 `autobuild` 里。

### 17.3 取数端同样受 PIT 约束（关键）

- 财务数据的 `available_at` 取 **公告日 NOTICE_DATE**，而非报告期；
- 只要 `notice_date > analysis_date`，该期报告一律不可用，**自动回退到上一期**，而不是"用最新的"；
- 时点前无任何已披露报告 → 抛 `NO_PIT_DATA`，宁可不分析；
- 价格与估值历史按 `trade_date ≤ analysis_date` 截断；分析时点晚于今天直接拒绝（PIT 无意义）。

这条让"历史某日回看"成为可复算的操作：指定 `analysis_date=2026-08-10`，系统只会用 8 月 15 日之前已公告的数据。

### 17.4 口径推导与"机械假设"的标注

- **TTM**：优先 `本期 + 上年年报 − 上年同期`；缺同期数据时退化为年化，并在 `derivations` 写明公式；
- **分位**：以可得历史为窗口（实测约 8.7 年而非满 10 年），窗口长度与样本数写入字段 `source`，不足 3 年直接不给；
- **DCF**：增速取近三年营收 CAGR（缺失则用最新同比）并逐年衰减，利润率/税率取最新报告期，WACC 9%、永续 2.5% 为默认值——全部标记 `mechanical_extrapolation`，**非市场一致预期**；
- **风险/催化剂**：只生成有数据依据的最小集（估值回归、增速、现金含量 3 条风险；定期报告法定截止日 2 条催化），方向与定价程度标 `?`（未知），不虚构事件。

### 17.5 界面上的闭环

1. 顶栏输入代码或名称 → 候选下拉 → 一键"分析"；
2. 取数状态条显示：**N/39 字段（与待补恒等于 39）、判断层覆盖 / 全维度覆盖、观测与代理条数、缺口分组、来源告警、推导过程（可展开）**；
3. 缺口面板即为补全向导：宏观/行业/公司的判断项按**字段类型**给控件——1–5 档用下拉、
   `-2..+2` 用档位选择、其余数值用数字框、`unit=文本`（一句话本质）用单行文本框；
   填完点"应用判断并重算"，人工判断以 `L3 + 形成日` 写入字段来源，覆盖率随之上升，
   分桶才会从"人工复核"变成正常结论。
   > 文本字段必须**单独一条渲染分支**：它提交的是字符串，走数值转换会被 `Number("…")=NaN`
   > 静默丢弃，用户填了内容却收到"尚未填写任何判断项"（A25 钉住这一点）。
   >
   > 定性档位（1-5 档）必须**带锚定含义**：档位不是自由评分，rubric 按 `(档-1)×2.5` 直接换算成
   > 档内分，选错一档整个因子偏 2.5 分。下拉选项显示「档位｜短语」、选中后回填整段行为描述
   > （如「4 档｜偏支持：有明确支持性政策或产业规划在途」），锚定量表本身就在 `specs.py` 里（A26 钉住）。

### 17.6 拒绝而非硬凑：三条失败路径

自动模式的正确性不只体现在"能出报告"，更体现在**出不了报告时说什么**。三条路径都返回可读 4xx + 稳定错误码：

| 错误码 | 触发条件 | 为什么不硬来 |
|---|---|---|
| `NOT_FOUND` | 检索无匹配的 A 股标的 | 不做模糊兜底，避免分析到同名的另一家公司 |
| `NO_PIT_DATA` | 分析时点之前无任何已披露定期报告 | 退无可退时必须拒绝，而不是借用未来报告 |
| `DCF_INFEASIBLE` | 机械外推的 DCF 股权价值 ≤ 0 | 见下 |

`DCF_INFEASIBLE` 的判定放在**装配完成之后**（`autobuild.build` 末尾，`_fill_report` 之后），而不是假设刚构造完时——因为此时输入与缺口清单都已齐备。异常对象携带 `payload={stock, analysis_date, input, fill}`，
接口层以 `{"ok":false, "error":{...}, "partial":true, ...payload}` 返回。界面据此把半成品载入 JSON 编辑器，并提示修正 `assumptions.dcf` 后重算。

这个设计的取舍：**宁可交出一份"数据齐备但结论缺失"的半成品，也不调参把 DCF 凑成正数**。前者使用者能接手，后者会得到一条看似成立、实则被参数操纵的估值区间。
边界也明确——半成品不是报告，`partial` 标记说明它未经估值成立性检验，不能当作结论引用。

## 18. 判断层的代理口径（哪些判断项能自动化，代价是什么）

早期版本把宏观/行业/公司的 15 个判断字段全部留空，理由是"没有可靠的公开机读口径"。
这个判断过粗：真正只能人读的只有 4 个。其余 11 个分三条路自动化——
**9 个**有公认的可复算代理（或本身就是观测值），**1 个**（10Y 利率）只是原先没找对源，
**1 个**（客户集中度）读年报正文原文。三条路都必须满足同一前提：可复算、可识别、可被人工覆盖。

> 客户集中度**有客观答案**，只是答案不在结构化接口里，而在年报正文的强制披露表中。
> 它现在走"公告原文 + 文本解析"（§18.8），落成**观测值（L1）**——既不是代理也不是判断，
> 所以已从"只能人读"的名单里移出；解析不出来时才回落到人工那一档。

### 18.1 分层原则：观测 ≠ 代理 ≠ 判断

| 类别 | 含义 | 标记 | 例子 |
|---|---|---|---|
| 观测值 | 数据源直接给出，无推断（含两个观测值的算术差） | `basis=observed` | M1 同比、制造业 PMI、10Y 国债收益率同比、大股东质押比例 |
| 代理值 | 由观测值按**固定公式**推断出的判断档位 | `proxy=true` + `derivations.method=proxy` | 行业增速=同业营收增速中位数；护城河=毛利率溢价+稳定性+ROIC 持续性 |
| 人工判断 | 研究结论本身 | `source_tier=L3` | 政策取向、渗透空间、投资逻辑强度、一句话本质 |

三类在**数据字典、推导表、证据链、界面**四处都必须能区分。人工值覆盖代理值时，`proxy` 标记必须消失——
它已经变成研究结论，不再是推断。

### 18.2 十一条自动口径

| 字段 | 代理口径 | 误差方向（写进 note） |
|---|---|---|
| `macro.m1_yoy` | 观测：人行 M1 同比 | 2025 年起口径含个人活期与非银备付金，与历史序列不完全可比 |
| `macro.pmi` | 观测：统计局制造业 PMI | 环比扩散指数，只反映方向与力度，不代表同比增速 |
| `macro.rate_10y_chg_yoy` | 观测：中债 10Y 国债收益率，`最新值 − 365 天前最近交易日`（bp） | 日终估值按次日可用；节假日前后锚点可能错位 1–3 天，对 bp 影响通常 ±2 以内 |
| `industry.industry_growth` | 同业（申万二级）营收同比**中位数** | ≠行业增加值；未上市份额大的行业会被龙头带偏 |
| `industry.price_trend` | 价=同业毛利率同比中位数（权重 0.6），量=同业营收增速中位数（0.4） | 成本端同步上行时价格上行被低估；量价背离时以价为主 |
| `industry.stage` | 由同业增速水平定档（0/5/12/20 分界），增速较上期回落 ≥10pp 降一档 | 无法区分"成熟但周期向上"与"成长中期"，高估风险大于低估 |
| `industry.concentration` | 公司营收 ÷ 同业营收合计（3%/8%/15%/30% 分界） | 份额高≠有壁垒，但与锚定语义（龙头/核心供应商）方向一致 |
| `company.moat` | 毛利率溢价（vs 同业同报告期，0.4）+ 近 5 年年报毛利率标准差（0.3，反向）+ ROIC>WACC 年份占比（0.3，反向） | 偏"高毛利+稳定"型；牌照/网络效应/低成本型会低估；资本密集型易被误读为无壁垒 |
| `company.mgmt_record` | 近 5 个完整年度现金分红年数（0.5）+ 质押比例（0.5，反向） | **未覆盖违规、承诺不兑现、减持**——判断强度明显弱于人工 |
| `company.pledge_pct` | 观测：中登质押比例（最新 ≤ asof 一期） | 存量口径，不反映质押用途与平仓线 |
| `company.customer_concentration` | **观测（不是代理）**：年报正文「公司前 5 大客户资料」里占比最高的一家，巨潮 PDF 解析（§18.8） | 只认第 1 行；五行之和须与合计对得上才采用；文字段形式的分母可能是主营业务收入，随值标注 |
| 其余 4 项 | 无代理，必须人工 | 见 18.4 |

各分项缺失时**按权重重归一化**，不补零；`_grade` 的档位映射对"越小越好"的指标（标准差、质押、份额反向）做整体翻转。

### 18.3 同业集合与 PIT

- **同业**取申万二级行业成员（中登质押表带 `INDUSTRY_CODE`，一次查询解决行业归属），样本 < 5 家时整个行业块缺失——不用 2-3 家硬算中位数；
- **业绩报表**不带可用公告日，因此按**法定披露截止日**判断可得性：一季报 04-30、中报 08-31、三季报 10-31、年报次年 04-30。方向保守：宁可用得晚，也不提前使用；
- **宏观**同样无发布日字段，按惯例保守后推：PMI 月末+2 天、M1 月末+15 天。时点未到则**回退到上一期**，不是"用最新的"；
- **质押快照**取 ≤ asof 的最新一期，asof 之后的快照一律排除；
- **国债收益率**走中债出版的 10 年期曲线（日频）：曲线是**日终估值**，当日 18:00 后才可用，因此每个数据点的 `available_at` 记为**次日**；一年前锚点取 365 天窗口内**最近交易日**，错位超过 10 天即判定序列不连续、整项留空（不插值）。

### 18.4 仍然只能人读的 4 项

| 字段 | 为什么不能代理 |
|---|---|
| `macro.policy_stance` | 需要读政策文本并判断"政策→行业→公司"的传导链，本质是研究结论 |
| `industry.penetration_space` | 需要行业总量与渗透率数据；用增速倒推会把周期反弹误判为渗透提升 |
| `company.logic_strength` | 预期差就是研究结论本身 |
| `company.logic_essence` | 一句话本质只能由人写，写出来即是观点 |

> 原列于此的两项已移出：10Y 国债收益率改走中债公开接口（`sources/chinabond.py`）；
> 客户集中度改读巨潮年报原文（§18.8），自动取到就是 L1 观测值，解析不出来才回落到本名单这一档。
> 判断层自动化的顺序是：先确认"真的取不到"，再决定"换源""用代理近似"还是"直接留空"；
> 三条都不成立时，还有第四条——**留一个人工输入位**（口径写在文档，不在面板展开）。

### 18.5 覆盖闸门随之改成"指标级 + 只看判断层"

维度级覆盖（"该维度有任何一个指标就算整维度覆盖"）在部分自动化之后会虚高：填了一条 M1 就宣称宏观已覆盖。
因此 §11 的 R7 闸门改为：

```
判断层覆盖 = Σ_{宏观,行业,公司} 维度中线权重 × 该维度可用指标权重占比
            ÷ Σ_{宏观,行业,公司} 维度中线权重
```

- **指标级**：分母是因子权重 × 指标权重，缺失的指标按 0 计，不补零；
- **只看判断层**：财务/行情/估值永远可得，计入分母会稀释信号，让"只做了数据整理、没做研究"的报告过闸；
- 全维度覆盖另存为 `total_ratio`，仅供读者参考，**不参与判定**。

实测：宁德时代判断层 80.7%（全维度 89.1%）→ 观察 8.03；平安银行 52%（银行毛利率不可比，护城河代理缺失）→ 人工复核。

### 18.6 字段账本必须能对账

自动化一旦分层，"哪些字段缺"就变成读者判断报告可信度的主要依据，因此清单本身不能失真。约束：

```
已填字段数 + Σ(待补分组字段数) = 数据字典字段数（39）
且 已填 ∩ 待补 = ∅，各组之间不重复
```

待补分四类，界面按类着色：

| kind | 含义 | 处理 |
|---|---|---|
| `judgement` | 研究判断，须人读 | 缺口面板可直接填，填后立即重算 |
| `data` | 可机读但自动模式刻意未取（避免把整理口径当事实） | 需要时手填 |
| `source` | 取数受限：限流丢 K 线、同业样本不足 | 补数或换时点重取 |
| `other` | 未归入上三类的残余 | — |

两条容易犯的错，都在 A19 钉住：

1. **取数降级字段静默消失**：`source` 类分组就是为此存在——丢掉 `market.turnover_pct` 时它必须出现在清单里，界面上的 `N/39` 才和缺口面板对得上；
2. **字典外字段混进账本**：例如总市值（亿元）曾经被写进 `data.market`，它既不进评分也不进估值（DCF 用股本×价格），却让 `filled_count` 虚高 1。此类纯展示字段一律不写入，需要展示就由前端从 `price_close × shares` 现算。

### 18.7 另外三类"取不到"的补救：兜底源、口径拆分、可比性闸门

早期版本的缺口面板里挂着五项"可机读但没取"或"取数失败"。逐项定位后发现是三种不同问题，处理方式也不同：

| 缺口 | 真实原因 | 处理 |
|---|---|---|
| `market.turnover_pct` / `vol_ratio_20d` | 东财行情主机（push2his）对自动化访问限流，K 线取不到 | **换源兜底**：K 线失败时切新浪财经日线（独立主机）；换手率新浪不给，用「成交量 ÷ 流通 A 股」现算 |
| `financial.wc_growth_gap` | 资产负债表只取了最新一期，且没有应收/存货科目 | **补科目 + 补期数**：同一张表加取 `ACCOUNTS_RECE`/`INVENTORY`，页码 8 期以覆盖上年同期 |
| `market.inst_hold_chg_pct` | 没有"机构持仓"专门报表 | **口径拆分**：改用十大流通股东明细，只统计 `IS_HOLDORG=1` 的合计占流通比，并声明"仅前十大" |
| `valuation.peer_pe_median` | 不是取不到，而是**从来没接线**（字典有、量规无、估值层早就留了 `peer_anchor` 入口） | **直接接上**：同东财板块 + 同交易日的 PE(TTM) 中位数 |

三条实现约束：

1. **兜底必须留痕**。K 线行带 `vendor` 字段，字段来源写成"东方财富-日K线（东财限流，改用新浪财经日线）"。用哪个源进了报告，读者能看见；不做「静默换源」。
2. **换手率的分母是流通股，不是总股本**。用总股本会系统性低估（有大量限售股的公司能差一倍）。流通 A 股取 `FREE_SHARES_A`，与当日成交量同为「股」，量纲一致。
3. **期间对比必须同期**。营运资本增速差比的是「上年同一报告期」（2026-09-30 vs 2025-09-30），不是上一季；机构持仓也一样——`END_DATE` 里混着「股东变动日」（如 2026-08-05），必须先筛标准报告期，否则两个不等长的时间段相减，方向都可能反。

**同业锚的可比性闸门**（`valuation.peer_anchor`）

同业 PE 中位数一旦填上，`run_relative` 就会把它乘 EPS 折成"隐含价位"。这在多数情况下是不成立的：宁德时代自身 11.6 倍、电池板块中位 31.8 倍，看起来"折价 63%"，但代工/整机/材料混在同一板块，倍数差来自生意不同，不是便宜。

因此定死：**只有本公司估值与同业中位相差在 0.5–2 倍以内，才折算价位**；超出范围时 `implied_price = null`，只报溢价/折价百分比并说明"倍数不可比，此处不给单点估值"。理由与 §7.3 一致——只给区间不给点位，尤其不能用一个不可比的锚倒推出一个看起来精确的价格。

### 18.8 客户集中度：公开接口没有这张表，但年报正文里有

**先排除"是不是我们没找对接口"**：东财 F10 经营分析（`PC_HSF10/BusinessAnalysis/PageAjax`）只返回三块——经营范围 `zyfw`、主营构成 `zygcfx`（按产品/地区拆收入）、经营评述 `jyps`，**没有客户/供应商表**。东财数据中心另外试过 7 个疑似表名（`RPT_F10_OP_CUSTOMER`、`RPT_F10_FN_CUSTOMER`…）全部返回"报表配置不存在"（9501）；同花顺 `operate.html` 的"客户"全是页面脚本里的"客户端"；新浪 `vCI_CustomerSupplier` 返回空页。
结论：**结构化接口里确实不存在这张表**。这一步没有冤案。

**但"接口没有"不等于"取不到"**。这张表是证监会《公开发行证券的公司信息披露内容与格式准则第 2 号》的强制披露项，就印在年报正文里：

```
公司主要销售客户情况
前五名客户合计销售金额（千元）                    165,061,533
前五名客户合计销售金额占年度销售总额比例                38.96%
公司前 5大客户资料
序号   客户名称    销售额（千元）   占年度销售总额比例
1      第一名       58,159,202        13.73%      ← 要的就是这个
2      第二名       47,127,609        11.12%
...
合计   --          165,061,533        38.96%
```

走巨潮资讯网的三个公开接口即可，**全程不需要令牌**（`sources/cninfo.py`）：

| 步骤 | 接口 | 备注 |
|---|---|---|
| 代码 → orgId | `POST /new/information/topSearch/detailOfQuery?keyWord=…` | 返回值里的 `plate` 决定检索用的 column |
| 年报检索 | `POST /new/hisAnnouncement/query`，`category=category_ndbg_szsh`（北交所 `_bj`） | 排除摘要/英文版/H股公告；按 `announcementTime` 做 PIT |
| PDF 原文 | `GET https://static.cninfo.com.cn/{adjunctUrl}` | 必须带 Referer；urllib 默认头会被挡成 500；PDF 只接受 GET（传空 body 会变 POST，回 405） |

**披露形态不统一，这是主要成本**（实测 9 家 A 股 2025 年报）：

| 形态 | 家数 | 能否得到"最大一家" | 样例 |
|---|---|---|---|
| 标准表（序号/客户名称/销售额/占比） | 5 | **能**，直接取占比列最高的一行 | 宁德 13.73%、格力 5.91%、海康 0.49%、东财 1.57%、金山 4.04% |
| 文字段写"第一名占 X%" | 1 | 能，但**分母可能不是销售总额** | 中芯国际 8.0%（分母＝主营业务收入）|
| 只有前五名合计 | 2 | **不能**，只能当上界 | 茅台 10.10%、紫金 39.75% |
| 无此披露（银行/保险） | 1 | 不适用 | 工商银行 |

**五条实现纪律**（1–4 对应验收 A24，5 对应 A33）：

1. **只认第 1 行**。最大客户必然是序号 1，不需要五行齐全。格力那张表跨页断裂、只解析到 4 行，5.91% 照样拿得到——若要求"五行俱全"，这张表会被整张丢掉。
2. **交叉校验**。五行占比之和应等于合计占比（实测 38.96=38.96、5.75≈5.74、2.01≈2.00，误差 ≤0.01pp，容差取 0.06pp）。这个校验能挡住"把销售额列当占比列"的错位；对不上时判 `table_inconsistent`、值留空，**宁可不要也不填错数**。
3. **占比不参与单位换算**。金额列有元/千元/万元三种写法，占比永远是百分数。当初做商用接口时踩过"按数值大小猜单位导致差十倍"的坑，这里从格式上就避开了。
4. **不许跨表接续**。客户表之后紧贴供应商表，序号同样从 1 到 5。若客户表某行漏匹配而循环"跳过继续找"，就会把供应商当成客户接上——阳光电源（300274）2025 年报正是这样凑出 5 行：和 25.11 其实是供应商五行之和（14.59+2.83+2.60+2.55+2.54），而合计取的是客户表的 16.96，一份本来可用的年报被判成 `table_inconsistent`。两道锁：解析窗口在"公司主要供应商情况 / 前 5 名供应商资料"处截断（截断后若连序号 1 都没有，说明锚点在客户表之前，反向恢复不截断）；序号断档立即收手（`break` 而非 `continue`）。**名称列长度上限同时从 24 放宽到 40**——出口企业第 1 名常是英文全称（`Algihaz Contracting Company` 26 字符），卡在 24 会把第一名整行漏掉，而漏掉第 1 行正是串表的起点。
5. **"空"要说清是哪一种**（验收 A33）。这一项的空有三种，对应三种完全不同的动作：**只披露前五合计** → 去翻年报（值本来就没有点估计，只能给上界）；**正文没这项** → 接受缺失或人工补录；**自动提取失败** → 重跑一次（年报已缓存，不必重新下载）。三种若共用一句"未提供"，读报告的人只能猜，而这恰是"这项是不是坏了"的来源。实现上失败原因从取数层（`raw.customer_error`）一路带到缺口说明，DQ 缺口允许被装配层的具体原因覆盖，MD 的前 10 条截断规则不吞带原因的条目。

**三档落地**（`autobuild._fill_customer_annual`，对应验收 A22）：

| 取到的形态 | 写入 | 来源等级 | 说明 |
|---|---|---|---|
| 单客户占比（表 / 文字段） | `value = top_ratio` | **L1** | 年报原文是一手材料，比东财那种二手整理高一级；推导里带页码、原文片段与校验结果 |
| 只有前五名合计 | **不写值** | — | 合计是"前五家加起来"，不是"最大一家"。宁德 38.96% 与 13.73% 是两件事，填前者会直接把 `risk.customer_conc` 顶到高风险档。上界写进缺口说明（"最大一家不超过 10.1%"）|
| 无披露 / 解析失败 / 未取到 | 不写值 | — | 回落到普通判断项，`why` 里区分是"年报没有这项"还是"这次没取到" |

**这块现在的形态**：

| 情况 | 面板显示 | 读者动作 |
|---|---|---|
| 年报有单客户占比 | 自动填上，计入 `已填 N/39`，来源显示"巨潮资讯-年度报告原文（PDF）" | 在推导里核对页码与原文即可 |
| 年报只有前五合计 | 「公司判断」卡里仍列这一行，说明里带"不超过 X%" | 读一次年报补单客户口径 |
| 银行/保险/未取到 | 同上，说明里点明原因 | 视为"集中度不可知"，**不要用 0% 表示** |

两条设计约束不变：

- **不做字段级的专门提示**。曾经给这一项单独挂过 `why` + 琥珀色「出处」横幅，结果同一张卡里另外两项只有一句说明，唯独它挂两段长文——把"一个人工字段"写成了特殊分支，面板也跟着变长。取数方法属于研究流程与文档，不属于缺口面板；面板只回答"这个字段还没填"。
- **没有复算口径的字段才开输入框**，且一律走 `kind=judgement` 同一条通路。像"无商誉""无应收"这类"公司本来就没有"的字段**不开放**输入框——一个空格子在旁边，人就会顺手填 0，那正是"用缺省值伪装成有数据"。

**关于评估过的两个商用源**（理杏仁「客户API」逐客户明细、今日投资「主要供应商及客户情况」只有前五大合计）：都试过，最后没用。令牌是付费前置、本框架要能裸跑；今日投资只有合计，唯一无假设的结论是等分下界 `合计 ÷ 5`，它**必然低估**集中度，只会让风险分偏乐观；而留下"配个环境变量就能用"的死代码最危险——读者会以为这块已经自动化了，于是不再读年报。既然年报原文能免费拿到同口径的数，这两条路不必再谈。

**这一节的教训**：上一版把"结构化接口里没有"直接写成了"这一项无法自动取"，漏掉了"披露文件本身"这条通路。财报类字段在接口里找不到时，先查披露准则要求它印在哪，再判断能不能读——**接口是二手整理，披露原文才是一手**。
