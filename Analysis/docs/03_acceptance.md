| A33 | 缺口原因可分辨（失败 / 只披露合计 / 没填） | ① 「最大客户收入占比」留空时必须说清是三种空里的哪一种：只披露前五合计→写上界与最坏档位；正文没这项→写该年报无此披露；自动提取失败→写失败原因，并说明已下载的年报会缓存复用、重跑一次通常能过；② 失败原因必须从取数层一路带到报告的 DQ 缺口（`raw.customer_error` → `input.data_notes` → `data_quality.gaps[].reason`），不许只留在取数告警里；③ 只有给了原因的字段才覆盖通用句，其余字段仍写「未提供（该指标按缺失处理，不补零）」，不许互相污染；④ Markdown 缺口列表的前 10 条截断规则不得吞掉带原因的条目；⑤ 界面「数据质量」页必须渲染 `field` 与 `reason` 两个字段，不许把缺口对象直接塞进 `esc()`（实测曾渲染成 `[object Object]`）；⑥ 值取到时不得留下任何缺口说明 | 把「取数失败」写成「用户没填」；缺口原因只进告警不进报告；截断把最该读的那几条截掉；界面缺口栏一片 `[object Object]` |

## 二、人检项（R1–R8 抽查 + R9 自动取数专项）

机检只能证明"结构合规"，不能证明"评分有意义"。以下 8 项由复核人抽查，每项给出具体动作；R9 针对自动取数另列。

| ID | 抽查动作 | 通过标准 |
|---|---|---|
| R1 | 从 `conclusion.bucket_mid` 出发，反向找"决定它的是哪一维" | 能说清主导维度；若为入池，最弱维度 ≥4.0 可核对 |
| R2 | 任取 3 个指标，用 `value` 对照量规表手算 `score` | 3/3 与报告一致（量规可对账，非黑箱） |
| R3 | 任取 1 个派生指标（PEG / 安全边际 / ROIC−WACC） | 用 `evidence_log` 的源字段可复算出该值 |
| R4 | 检查 `evidence_log` 中每条 `available_at` | 全部 ≤ `analysis_date`；无"用未来数据" |
| R5 | 读 `falsification` 每条 | 是**可观测数字阈值**（非"景气度下降"类空话），且指明影响哪一维度 |
| R6 | 读 `catalyst_calendar` | 日期不早于分析时点；`priced_in=已定价` 的利好带兑现风险提示；未证实传闻不计分 |
| R7 | 读 `valuation.dcf.warnings` 与 `synthesis.mode` | 终值占比>70%、WACC 超区间、并集/单法均有文字说明，无静默处理 |
| R8 | 抽 1 个 L3 来源字段 | 报告中能被识别为低等级来源，且已体现于置信度（DQ/来源惩罚） |

**R 项任一不通过 → 整份报告不予采信（退回补充数据或降级为"观察"）。**

### 自动取数的附加人检（R9，抽查 1 只标的）

1. 顶栏输入代码后，进度条显示的 `N/39` 与面板中"待补分组"字段数之和应等于 39（无重复、无遗漏）。待补分组有四种 `kind`：`judgement`（须人读研究判断）、`data`（可机读但自动模式未取）、`source`（取数受限：限流/缺表/样本不足，说明里会写清具体是哪种）、`other`。
2. 抽查 2 个自动填充字段，回原始公告核对数值；再核对 `as_of`（报告期）与 `available_at`（公告日）是否被正确区分。
3. 展开"推导过程"，确认每个计算字段都有公式；机械假设应能看到 `mechanical_extrapolation` 标注。
4. 把某只标的的 `analysis_date` 改到中报披露之前，确认页面顶部读数（报告期/披露日）随之回退——这是取数端 PIT 生效的直接证据。
5. 换一只薄利重资产标的（如北交所部分个股），确认它给出的是 `DCF_INFEASIBLE` + 已载入编辑器的半成品，而不是崩溃或硬凑出来的估值；在编辑器里把 `assumptions.dcf` 的净债务改为负值（净现金）后点「分析」，应能正常出报告。
6. 核对判断层的代理项：状态条应显示"观测 M · 代理 N"；展开推导过程，每个 `method=proxy` 的条目都必须有**公式**与**误差方向说明**（例如"资本密集代工易被误判为无壁垒"），且该行有琥珀色竖线标记；证据链表的"性质"列显示"代理"。用缺口面板人工填同一字段后重算，该字段的"代理"标记必须消失——它现在是人给出的研究结论，不再是推断。
7. 抽查 1 个 `kind=source` 的待补字段（如行情限流时的 `market.turnover_pct`），确认它确实没被填入而非填了默认值；若被填了 0 或中位数，即判定为"用缺省值伪装成有数据"，直接不通过。
8. 核对兜底源与同业锚：① 换手率的推导式必须是「成交量 ÷ 流通 A 股」，分母不能是总股本；② 若 K 线来自新浪，字段来源要写明"东财限流，改用新浪"，不能仍标东财；③ 同业 PE 中位数与本公司倍数相差超过 2 倍（或低于 0.5 倍）时，估值页的「同业锚定价」必须显示"不给"，而不是一个折算出来的价格。
9. 机构持仓变化：展开推导，确认比的是两个**标准报告期**（如 2026-09-30 vs 2026-06-30），而不是"报告期 vs 某个股东变动日"（如 2026-08-05）——后者是两段不等长的时间相减，方向可能反。
10. 核对 10Y 利率同比：证据链里该字段的 `as_of`（曲线数据日）与 `available_at` 必须相差 1 天，且 `available_at ≤ analysis_date`；推导式应写成「某日 10Y x.xxxx% − 某日(一年前) x.xxxx% = ±xx.xbp」，两个日期相差 365±3 天。若分析时点距最新交易日不足一天却已用上该日曲线，说明前视，判定不通过。
11. 核对客户集中度（`company.customer_concentration`）：先看它是**自动填的还是空着的**。自动填了，说明年报里读到了单客户占比——去「推导过程」核对页码与原文片段，来源应为「巨潮资讯-年度报告原文（PDF）」、等级 `L1`，且 `as_of` 是年报期末而非今天；空着则看缺口说明写的是「年报只披露前五名合计 X%，最大一家不超过该值」还是「年报没有这项披露」，前者要读一次年报补单客户口径，后者视为不可知。**任何情况下都不许把前五名合计当最大一家填进去**。若这一行比同卡另外两项多挂一段「出处」或「可手填」标记，说明人工项又被写成了特殊分支，判定交互不合格。手填一个数后点「应用判断并重算」，字段应以 `L3 人工研究判断（界面录入）` 入账；不填时该指标必须是 `null/missing`，绝不能显示 0。反向检查：`financial.goodwill_ratio` 这类「公司本来就没有」的字段**不得**出现输入框（否则诱导把缺失填成 0）。
选档位时先看下拉里的短语与行内说明：政策取向应能读到「明显抑制 / 中性 / 强支持」，渗透空间应能读到「>70% 空间有限 / <10% 导入期」，逻辑强度 4 档应点明「存在被低估的预期差」——看不到这些说明，选出来的档位就没有依据。
另外在「公司判断」卡里给**一句话本质**填一句中文（如"全球动力电池龙头，储能是第二曲线"）后点「应用判断并重算」，必须提示"已合并 1 项"且结论首句显示这句话——若提示"尚未填写任何判断项"，说明文本字段又被当成数值校验了。
12. 核对披露节奏：报告里"最新报告期"若是季报（如 2026-09-30），必须能同时看到"最近一期年报"是哪一期、哪天公告；两者不是同一个日期。客户集中度无论是自动取到还是手填，证据日志里它的 `as_of` 都应是**年报期末**、`available_at` 应是**年报公告日**（不是今天），数据质量备注里应有"只在年报披露的字段…不随季报前移"一句；若它出现在"数据超期项"里，说明周期又被写成季频，判定不通过。

## 四、明确的"不做"（验收时不得被要求）

1. 不输出买卖指令、仓位比例、入场/离场点位、胜率与收益承诺；
2. 不对单一标的给"必涨/必跌"判断；结论一律条件化并附证伪条件；
3. 不做未来函数补偿（例如用后验数据"修正"当期评分）；
4. 不在数据缺失时用行业中位数/历史均值**静默**硬填（只降级并声明）；判断层的代理值必须写成"可复算公式 + 误差方向 + 代理标记"三件套，并在证据链里与人工结论区分开——没有这三件套的推断式填充不予通过（A18）；
5. 不用单一总分替代维度拆解（必须能看到每个指标的档位与依据）。

## 五、已知限制

1. **样例为演示数据**（虚构标的 `XX0000.DEMO`），数值不代表任何真实公司；
2. DCF 为简化 FCFF（不含分部门、不含期权、不做周期正常化），对强周期/金融类标的需替换口径。**金融类（银行/保险/券商）整体会缺一批字段**：它们用另一套资产负债表模板，通用取数拿不到应收/存货/有息负债，因此 `int_debt_ratio`、`wc_growth_gap`、`goodwill_pct`、`roic` 会成组缺失（`kind=source`），闸门会把结论压到"人工复核"。这是口径问题，不是取数 bug。
3. 风险矩阵的 P/I 为主观 1–5 档，需在 `rationale` 或研究底稿中给出打分理由；
4. 事件日历依赖外部输入，框架不自带公告抓取；
5. 短线桶仅作参考，未做盘中流动性与冲击成本建模；
6. **判断层代理有明确失效面**，必须按标的类型重读：护城河代理用毛利率溢价 + ROIC>WACC 年份占比，对资本密集型代工（如晶圆制造）会低估壁垒；对银行/保险，毛利率不可比，护城河与卡位代理直接给空而非硬套；管理层代理只看分红连续年数与质押比例，读不出诚信瑕疵与资本配置能力。代理值一律带 `proxy` 标记，最终采信前应由研究人改写或确认。
7. 覆盖闸门只解决"有没有数据"，不解决"数据对不对"。判断层覆盖 81% 不代表结论可靠，仍须过 R1–R9。
8. **两个字段的口径弱于名字**：`market.inst_hold_chg_pct` 只覆盖前十大流通股东（新进/退出会同时改变分子分母），是方向性证据；`valuation.peer_pe_median` 用的是东财板块（与申万二级不同源，且板块内可能混着完全不同的生意）。两者都不宜单独支撑结论。
9. **K 线兜底源可能换**：东财限流时切新浪，成交量口径同为「股」，但缺少成交额；若未来两个源都不可用，交易面会整体缺失（`kind=source`），此时不要手工补一个"看起来合理"的换手率。
