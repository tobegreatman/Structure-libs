# 深度评估：stockframe 个股分析框架

- **评估对象**：`src/stockframe/`（9.5k 行）、`tools/`、`tests/`（168 例）、26 项机检、`docs/`（1.5k 行）
- **评估日期**：2026-10-25
- **评估方式**：全量读码 + 复跑验收 + 真机取数（000001 平安银行）+ 12 组异常输入注入
- **评估立场**：假设这套系统要对自己的"入池/观察/回避"负责，而不是只对"能跑通"负责

---

## 0. 结论先行

| 维度 | 评级 | 一句话 |
|---|---|---|
| 工程纪律（PIT、可追溯、文档同源） | **A** | 同类个人项目里少见，证据链是真的能翻回去 |
| 输入健壮性 | **D** | NaN/Inf/负价/越界档位/拼错字段名，全部静默通过 |
| 跨行业适用性 | **D** | 银行股实测：净债务按 0、EBIT 率 43.7%、安全边际 +95.7% |
| 权重与信号一致性 | **C+** | 一个人点一档护城河 = 0.27 分；ROE 从 8% 到 20% 只动 0.16 分 |
| 方法论有效性（能不能预测） | **未验证** | 全仓 0 行回测，阈值（7.0/5.0/3.5）无来源 |
| 可运维性 | **B** | 薄壳设计干净，但无输入契约、无运行时限流 |

**一句话**：它现在是一台**可追溯的记账机**，还不是一台**可验证的判断机**。
记账机这部分做得相当好——每一分都能拆到字段和页码；但"这一分意味着什么"，目前没有任何证据。

## 1. 先说实话：这些地方做得比大多数同类项目好

不客套，逐条给位置：

1. **三时点 PIT + 违约即终止**（`pit.py`）。`as_of / available_at / period_end` 分开，`available_at > analysis_date` 直接抛 `LookAheadError`，L4（媒体/传闻）`ProvenanceError` 拒入评分。不是"警告后继续算"，而是终止。
2. **缺失不补零，重归一化留痕**（`rubric.py:eval_factor`）。缺指标时按可用权重重算，同时记 `available_weight_ratio` 与 `renormalized`，报告里能看出"这一档建立在更少证据上"。
3. **决策先于分数**（`decision.py`）。硬红旗 → 回避，走在 7.0 分之前。高分掩盖 ST/立案这类错误被结构性排除了。
4. **文档与代码同源**（A11）。量规表由 `specs.py` 生成，改阈值只能改代码，文档漂移会被机检抓住。
5. **薄壳服务端**（`server.py`）。界面不复制任何评分逻辑，A14 用同输入比对 CLI 与 API 同分——"界面分数 ≠ 命令行分数"这类经典事故被提前堵死。
6. **拒绝而非硬凑**。`DCF_INFEASIBLE` 回半成品让用户改假设、`NO_PIT_DATA`、10Y 利率同比缺锚点不插值、同业倍数不可比就不给折算价位（A20）。这几条是真正的专业判断，不是工程炫技。
7. **测试是真测试**。168 例里大量是"错误必须被抓住"的负样本（缺序号不凑、跨页取第 1 名、匿名客户表、年报字段不按季频判超期）。

这套纪律值得保留，下面的批评都建立在"它已经比多数同类强"的前提上。

## 2. P0：会让报告出现错误数字的问题

### P0-1 没有行业适用性闸门（真机实测：000001 平安银行）

复现：

```bash
PYTHONPATH=src python -m stockframe.server --port 8771
curl -X POST localhost:8771/api/fetch -d '{"query":"000001","analysis_date":"2026-10-23"}'
# 再把返回的 input 贴进 /api/analyze
```

实测结果（2026-10-23 时点）：

| 输出项 | 实际值 | 应该有 |
|---|---|---|
| 分桶 | 人工复核（R7_COVERAGE，判断层覆盖 56%） | 人工复核 ✓（但拦住它的是覆盖闸门，不是行业判断） |
| 综合分 | **7.12**（已过入池线 7.0） | — |
| 公司维度 | **10.0**（满分，但只有 2 个指标有数：管理层 5 档 + 质押 0.13%） | 不应在 30% 覆盖下给满分 |
| 估值维度 | **9.34** | 银行不适用 FCFF |
| DCF 区间 | 24.58 – 33.28 元（股价 11.20） | 不应计算 |
| 安全边际 | **+95.7%** | 不应计算 |
| 净债务假设 | **0**（"资产负债表为空→净债务按 0"仅是一条 warning） | 银行无此概念，应拒绝 |
| EBIT 率 | **43.66%**（银行"营业利润率"） | 口径不存在 |
| `company_type` | `steady_growth`，同时 DCF 营收路径 **-5% → -2%** | 字段自相矛盾 |

三个连锁问题：

1. **`company_type` 写了不用**。`engine.py:323` 只是把它抄进报告，全仓无一处分支（`grep company_type` 只有 3 处：声明、赋值、抄写）。所以"成长/稳态"没有任何模型含义。
2. **PB 取了不用**。`market.pb`、`market.pctile_pb_10y` 每只票都取，但 36 个指标里**没有任何一个用 PB**（见 §4 表）。银行股最该用的估值锚被取回来摆在界面上不参与判断。
3. **DCF 对不适用行业不拒答**。设计文档 §7 只对"股权价值为负"拒答（`value_per_share`），对"这个行业根本没有 FCFF"没有任何前门。

> 这不是"精度不够"，是**报告里出现了现实中不存在的数字**，而且带一个 +95.7% 的安全边际。它能被停在"人工复核"，靠的是判断层只填了 56%——一旦用户把三个判断项补齐（我实测：补到 3 档后 6.35 / 观察），这份报告就成了一份"看起来正常"的银行研报。

### P0-2 输入没有类型/范围契约，污染静默入模

`validate_structure()`（`datadict.py:90`）只检查顶层键和 `risks/catalysts` 条数。字段值本身**没有任何校验**——没有 `isfinite`、没有区间、没有类型、没有"字段名是否登记"。实测：

| 注入 | 结果 | 严重性 |
|---|---|---|
| `roe_ttm = NaN` | 财务维度 7.81 → **6.61**，落进"最差档"当真实分数；**置信度仍 0.924 不变** | 静默劣化 |
| `roe_ttm = +Inf` | 财务 7.81 → **8.21**，综合 7.72，仍 **入池** | 静默抬分 |
| `moat = 9`（越界） | 静默当"缺失"处理，只掉置信度 0.013；录入错误消失 | 静默吞错 |
| `moat = 4.7` | `int(4.7)` → 4 档，无提示 | 静默取整 |
| `price_close = 0` | 接受；安全边际变 None，估值维度照算 | 静默 |
| `logic_essence = 12345` | 结论首句："一句话本质：12345｜…" | 静默 |
| 字段名拼成 `roe_typo` | 完全无提示（未知 `field_id` 不校验），只是 roe_ttm 变成缺失 | 静默 |

根因在 `rubric.py:_band_of`：`Band.contains(NaN)` 对首带（`lo=None`）返回 **True**，对末带（`hi=None`）也返回 True —— 于是 **NaN 得最差分，+Inf 得满分**，两者都被当成"有效数据"参与加权，还不会触发缺失惩罚。这是本次评估里**唯一一个"让脏数据自动变成分数"的机制性缺陷**。

修法（约 30 行）：
```python
# pit.check_field 里，value 为数值时
if isinstance(v, float) and not math.isfinite(v):
    raise LookAheadError(f"字段 {field_id} 的值非有限数：{v!r}")
# validate_all_fields 里，字段名必须已登记
unknown = [f for f in registry if f not in FIELD_REGISTRY and f not in DERIVED]
if unknown: raise InputError(f"未登记字段（疑似拼错）：{unknown}")
# 定性档位：必须是 int 且 1<=v<=5；文本字段 unit=文本 → 必须是 str
```

### P0-3 亏损/负值没有分支

| 注入 | 结果 |
|---|---|
| `PE = -35`（亏损） | 估值维度 **7.12**、安全边际 **+12.4%**、区间 33.13–39.90 —— 把亏损股的负 PE 当分位用 |
| `EPS = -0.8` | 合成区间 **low = -17.6**（报告里出现负股价），mode=union，schema 通过 |
| PE 负 + EPS 负 | 同上，仍 **入池 7.68** |

`percentile_band(负值)` 只按分位论"偏低/偏高"，不看符号；`implied_price_range` 直接 `hist_p25 × eps`，没有正数约束。三个必须加的判据：

1. `PE ≤ 0` 或 `EPS_TTM ≤ 0` → **相对估值不适用**，并给出替代口径（PB/PS）；
2. `implied_price ≤ 0` → 该法置 `available=False`，不许进合成；
3. `combined_range.low ≤ 0` → 报告拒绝输出区间（现在会输出 -17.6 元）。

## 3. P1：让结论"看起来准"但站不住的问题

### P1-1 数据侧缺失不影响分桶（只降信心）

实测删字段（样例基线 7.64 / 入池）：

| 情形 | 综合分 | 分桶 | 缺字段 | 置信度 |
|---|---|---|---|---|
| 基线 | 7.64 | 入池 | 0 | 0.924 |
| 财务删 7 个（只剩 ROE + 营收增速） | **7.57** | **入池** | 7 | 0.742 |
| 估值删 5 个（只剩 PE/EPS） | **7.64** | **入池** | 7 | 0.781 |
| 交易面 5 个字段全删 | **7.52** | **入池** | 5 | 0.847 |

覆盖闸门（`R7_COVERAGE`）只算宏观/行业/公司三层，这是有意的（§18.5 的理由成立：财务行情永远可得，计入分母会稀释信号）。但**反面没有规则**：财务只剩 2 个指标、交易面整块没数，结论文字不变、分桶不变。

而且 `dim_min >= 4.0` 只用"有分的维度"求最小（`decision.py:105`），缺失维度不参与——所以"维度全绿"可能是"只测了两个维度"。

建议：加 `R8_DATA_COVERAGE`（财务/估值/交易任一维度指标覆盖 < 0.6 时，结论降级为"人工复核"或至少把桶名改成"观察（数据不足）"），或直接规定 `confidence < 0.5 → 人工复核`。

### P1-2 权重把"可审计的事实"和"一个人点的档"放在了同一张表里

36 个指标的**有效权重**（维度权重 × 因子权重 × 因子内权重）前 12 名：

| 排名 | 指标 | 中线有效权重 | 性质 |
|---|---|---|---|
| 1 | `company.moat`（护城河 1-5 档） | **0.1100** | 人工判断 / 代理 |
| 2 | `valuation.dcf_margin` | 0.0720 | 派生（假设驱动） |
| 3 | `industry.concentration` | 0.0490 | 人工判断 / 代理 |
| 4 | `company.logic_strength` | 0.0440 | 人工判断 |
| 5 | `company.mgmt_record` | 0.0396 | 人工判断 / 代理 |
| 6 | `risk.matrix_score` | 0.0360 | 计数驱动（见 P1-3） |
| 7 | `industry.industry_growth` | 0.0336 | 观测（同业中位） |
| 8 | `val.pe_pctile` | 0.0336 | 观测 |
| 9 | **`financial.roe`** | **0.0320** | **可审计财报数** |
| 10 | `val.peg` | 0.0320 | 派生 |
| 11–12 | `cat.density` / `cat.next_event` | 0.0300 | 日历驱动 |

- **定性（1-5 锚定）合计 32.0%**，其中护城河单指标 11%。
- 灵敏度实测：`moat` 4→5 = **+0.27**；`logic_strength` 3→4 = +0.11；`policy_stance` 3→4 = +0.05。
- 而 **ROE 从 8% 走到 20%（跨三个量规带）= 只 +0.16**。

也就是说：**点错一次护城河 = 把 ROE 从两位数打到 20% 的 1.7 倍影响**。这不是"权重可讨论"，是权重与"证据强度"反向排序——最不可审计的项权重最大。A26 已经把"选错一档 = 偏 2.5 分"钉住了，但没管"这一档值多少总权重"。

同时存在**双重计数**：护城河代理 = 毛利率溢价（0.4）+ 毛利率稳定性（0.3）+ ROIC>WACC 年份占比（0.3）。而 `financial` 维度的 `gm_trend`、`roic` 已各算一次。高毛利 + 高 ROIC 的公司被奖励两次，且第二次是以 11% 的权重。

建议：让"可审计数据"的有效权重 ≥ 主观档位；护城河代理去掉 ROIC 项（或与 financial 维度做正交化），并在报告里显示"本次综合分中主观档位贡献 X 分"。

### P1-3 风险与催化是"计数型"指标，跨股票不可比

`matrix_score = 10 × (1 − min(20, Σ clamp(P×I−8, 0, 17)) / 20)`。同一批风险，改条数就改分：

| 输入 | 风险维度分 |
|---|---|
| 1 条（P4×I4=16） | **8.0** |
| 2 条 | 7.5 |
| 3 条 | 7.5 |
| 5 条（样例） | 7.0 |
| 3 条 + 两条 P5×I5 | **0.0** |

两个结构性后果：

1. **不写风险 = 风险可控度更高**。最低要求 3 条，恰好凑 3 条轻风险的标的，风险分天然高于老老实实列 6 条的。
2. **饱和**：两条 25 分风险就把分数打到 0，第三条灾难性风险"免费"。风险维度的分辨力在尾部消失。

而自动模式的 `_auto_risks()` 条数**随可得数据浮动**（PE 分位有就 +1，净利同比有就 +1，现金流有就 +1）——同一家公司换数据源，风险分就变。这直接违反"同一档位同一含义"的初衷。

催化同理：`density_score = min(10, Σ 强度权重)`，多列两个"弱"事件就能把中线催化分从 5 拉到 10；而自动补的法定披露日（2 条 × 2.5）已经给了 5 分基线，**这个 5 分不含任何信息**。

建议：风险改率指标（`Σpenalty / 风险条数` 或用最大 P×I 为主、条数为辅），饱和曲线改渐近（如 `10×exp(−penalty/12)`）；催化按"窗口内最强事件 + 密度分位"而非绝对累加，自动日历事件权重设 0。

### P1-4 阈值没有校准，也没有回测

`7.0 入池 / 5.0 观察 / 3.5 回避 / 单维 ≥4.0 / 覆盖 ≥0.60 / WACC 8–12% / g ≤3% / TV ≤70%`——这些数字在文档里都只有"看起来合理"，没有一处给出**历史依据或校准过程**。全仓 `grep -i backtest|ic|calibration` 为空。

这是可以理解的取舍（框架定位是"研究复核"不是"选股信号"），但它带来一个未言明的落差：报告用两位小数的 `7.12` 和明确的"入池线 7.0"，**形式上像阈值，实质上是约定**。读者会当阈值用。

最低成本的做法（不需要预测收益）：
1. **权重敏感性**：维度权重 ±20% 抖动 1000 次，统计"分桶翻转率"。翻转率高的标的，报告应主动标注"结论对权重敏感"。
2. **单指标贡献分解**：报告里给出"综合分 = 各维度贡献"的瀑布，让读者看见 7.12 里有几分来自主观档位。
3. 若愿意做回测：用现有 `eastmoney` 取数能力拉 5 年面板，算分桶的 rank-IC 与分桶年化收益差；**这一步不做，"7.0"就永远只是约定**。

## 5. 这套系统能回答什么、不能回答什么

**能回答（且答得比人稳）**
- 这份研究**自洽吗**：结论 → 维度 → 因子 → 指标 → 量规带 → 字段 → 来源/页码/披露日，链条可回放。
- 证据**齐不齐**：缺哪一层、缺几个字段、缺的是判断项还是数据项。
- 时点**干净吗**：有没有用未来信息（A15/A21 钉得住）。
- 有没有**硬伤**：ST/立案/审计非标/红旗数，优先于任何分数。

**不能回答（目前所有输出都在这条线上）**
- 这家公司**值多少钱**：DCF 的营收路径、EBIT 率、WACC、g 全是外生假设，模型只做算术。银行案里它算出 24.58–33.28，那只是假设的镜像。
- 这个分数**能不能预测收益**：无回测、无 IC、无分桶收益差。7.0 是约定，不是发现。
- **跨行业可比**：没有行业模板，银行/保险/地产/周期/亏损/次新都在同一套 36 指标里打分。
- **一个行业值不值得看**：行业维度 14% 权重，却只有 5 个指标，其中 3 个是人点或代理。

## 6. 修复清单（按投入产出比排序）

## 8. 总评

这套系统的**骨架是对的**：PIT、证据四要素、缺失不补零、决策先于分数、文档同源——这五件事做到了，就把"拍脑袋出结论"最常见的五种借口堵住了。它的 168 个测试和 26 项机检，绝大多数在守"内部自洽"，这一点做得比绝大多数同类项目认真。

但它目前守的是**过程的诚实**，还没守**结果的正确**：

- 输入层没有契约，脏数据能变成分数（P0-2，机制性缺陷，30 行可修）；
- 没有行业适用性判断，银行股能算出 +95.7% 的安全边际（P0-1，最伤专业可信度）；
- 权重把最不可审计的项放在最重的位置，ROE 的 3.4 倍影响还比不上点一次护城河（P1-2）；
- 阈值没有校准，形式上像发现，实质上是约定（P1-4）。

按 §6 的 P0 + P1 做完，它会从"可追溯的记账机"变成"不会说错话的记账机"。要变成"可验证的判断机"，缺的那一步只能靠回测——**而这一步，恰好是这套框架现在唯一没有任何代码覆盖的部分**。

## 14. 档位判定提示词（2026-10-25 五轮）

### 14.1 问题

`prompts.txt` §一–§三 解决的是"信息怎么取、结论怎么论证"，落点是"成立/不成立""阶段""强度"，
**没有落点到一个 1–5 的整数**。中间这层映射一直由人拍：同一份材料，A 填 3、B 填 5，
系统就给出 5.0 分与 7.5 分两个结论，且两边都能自圆其说。这是打分差异的主要来源，
比任何算法细节都大。

### 14.2 做法

新增 `prompts_grading.txt`，把三个字段的判档钉成**互斥判据 + 排除顺序 + 改档触发条件 + 回填片段**：

| 字段 | 判档骨架 | 关键分界 | 该防的偏差 |
|---|---|---|---|
| `macro.policy_stance` | 三问：方向 → 对象（是否针对本行业）→ 阶段（信号/在途/兑现） | 4 与 5 差在"钱和量动没动"：补贴到账、中标落地、强制标准执行、国产化考核 | 把"文件提到"当支持、把"国家战略"当 5、把"补贴退坡"当 1、把景气下行当政策抑制 |
| `industry.penetration_space` | 先算渗透率（分子/分母/排除项 → 数值 → 再对区间），边界仍按区间定档 | 区间互斥（>70 / 50-70 / 30-50 / 10-30 / <10），不允许四舍五入去够档 | 分母膨胀（TAM 冒充 SAM）、用国产化率/集中度偷换、用增速倒推、只看低不看天花板 |
| `company.logic_strength` | 四问：路径是否明确 → 有无预期差 → 是否被定价 → 可证伪且显著错判 | 5 档要双条件（有阈值 + 现价隐含假设明显不成立）；只有一条降 4 或 3 | "市场尚未认知"当论据、股价涨跌当验证、好公司误当有预期差 |

配套三件事：
1. **§零 先算钱**：一档值多少综合分（政策 0.05 / 渗透 0.05 / 逻辑 0.11，实测非估算），
   并给出 1↔5 最大摆幅 0.20 / 0.21 / 0.44。分桶边界 5.0/7.0，逻辑强度错两档就足以翻桶——
   "三个字段哪个值得多花时间"从此有量化答案。
2. **§四 三方向交叉校验**：单看自洽、组合打脸的五种情形各给默认解释（如"政策 5 + 渗透 1"
   多半是分母被做小或政策只是提及）。
3. **§五 回填与机械检查**：`as_of` 与 `available_at` 的区别、时效阈值（31/92 天，1.5×/2× 降档）、
   L4 禁入、交易指令词拦截、档位必须是整数。
4. **§六 批量模式**：给一个标的、一次要三个数字时，用一层外层纪律包住三个模板——
   每档独立取证、不许引用另一档结论、三档判完才看交叉校验；输出三档汇总表
   （字段｜档位｜命中锚文｜不是相邻档的理由｜改档触发），**填不出来的那一行就是薄弱环节**。

### 14.3 防漂移

判据表逐字抄自 `specs.py` 的 `ANCHORS`，界面下拉框悬停显示同一段字——三处必须同时改。
`tests/test_grading_prompts.py` 逐条对账：五档判别词是否都在提示词里、字段 ID 是否点名、
回填片段是否合法 JSON、§零 的权重链是否与 `DIMENSIONS` 一致（重算 `2.5 × 维度×因子×指标`）。
锚文历史上改过两次、两次都漏改文档，所以这次用测试钉住，不再靠记性。

## 16. 一句话本质并入独立版（2026-10-25 七轮）

### 16.1 难点：它不是第四个档位

前三个字段的模板结构是"输入 → 判据表（5 档锚文）→ 排除顺序 → 输出档位"。
一句话本质是**文本**（`company.logic_essence`，≤200 字），没有档位、没有锚文、
也没有"命中哪一档"这回事。照抄前三节的结构会得到一个四不像：判据表填什么？

所以先定它的角色，再定写法：

> **它不是第四个判断，而是逻辑档位的可读化证明。**
> 前三个是"评出来的"，这一句是"写出来的"；同时它是那一档的**刹车** ——
> 这句话写不出"指标 + 阈值"，第三节的 5 档就不成立。

### 16.2 补进去的五件东西

| 内容 | 解决什么 |
|---|---|
| 骨架三块表（收益来源 / 兑现路径 / 证伪条件，每块配"不合格的样子"） | 让它有固定形状，不同人写出来能横向比较 |
| 7 条硬规则（先取证、≤200 字、拆 β/α、只装一个主逻辑、数字可回溯、写反方、与 `logic_items` 对齐） | 把"写得像样"换成"写得可审计" |
| 五个坏句子 → 改法对照表 | 抽象规则对模型没用，反例才有用："行业龙头受益于景气""估值有安全边际""具业绩弹性""市场尚未认知""未来三年 30%" |
| 与逻辑档位的双向校验表 | 文字与档位互相约束：写不出阈值 → 最高 4 档；"受益于景气"类 → 强制 1 档；拆不出 β/α → 最高 2 档 |
| 回填片段（`value` 是一整段中文，示例 130 字） | 与其他字段结构一致，但 `value` 类型不同，必须示范 |

回填片段的位置也统一了：原本本质那段在第四节内部，另外三段在最后一节，
复制时要跨节找。现在四段全部挪到「交付结构」，按 政策 → 渗透 → 逻辑 → 本质 排列。

### 16.3 一个必须点明的限制

**本质没有独立标尺。** 单看一句话，判断不了它该有多硬 —— 只能对照逻辑档位。
所以模板里写了一句话："只判本质时，先按第三节的四问在心里定一次逻辑档位（哪怕不输出），
再用双向校验表对照。" 否则模型会写出一句很好听、但不知道对应几档的话。

这与第三节 Q4 是同一条规则的两种形态：Q4 是判档，本节是复核。

### 16.4 守卫与回归

新增 `test_standalone_prompt_covers_logic_essence`：回填键、200 字限、`logic_essence`
片段、三条档位约束（最高 4 / 强制 1 / 最高 2）必须同时在。缺任何一条，本质就退化成
"写句漂亮话"——没有键回填不了，没有字数限制会被输入框截成半句，没有档位约束则
文字与档位各说各话。

顺带实测：示例句 130 字、`check_value('company.logic_essence', ...)` 通过、
`scan()` 无违禁词、键序与真实输入一致。

## 18. 研判四行重写：从"机制术语"改成"决策语言"（2026-10-25 九轮）

### 18.1 用户的原话与三个病因

> "新增四行，不易读懂，也看不出方向建议"

拆开是三件事，前两件是文案，第三件是数据缺失：

1. **符号堆叠**：`入池 7.64 · 距 7.0 线 +0.64 · R6_SCORE_BAND`。一行里三个抽象记号，
   读者要自己完成"7.64 比 7.0 大 0.64，所以还差 0.64 掉出去"这一步换算。
2. **术语前置**：`翻转`、`边界`、`判断层占 44%`、`两法中枢分歧 14.4%` 都是内部词汇，
   每行只说了"是什么"，没有一句"所以呢"。
3. **方向只报了一半——这是最实质的缺陷**。上一轮只算"往下掉多少分翻桶"，没算"往上还有没有档"。
   于是一个入池标的看起来像"上面还有空间"，实际上**入池就是最高档**，`room` 根本不存在。
   方向感缺失不是措辞问题，是字段缺失。

### 18.2 改法：四行重命名，每行补一句"所以呢"

| 原 | 新 | 主句干了什么 |
|---|---|---|
| 定位 | **结论** | 档 + 分 + 桶内位置 + 三组贡献相加 ≈ 综合分 + 置信 |
| 翻转 | **方向** | "档位已经到顶：往上没有更优的一档可升，能变的只有往下，而往下只剩 0.64 分（0.26 档）" |
| 触发 | **盯谁** | 最先翻的是谁、掉几分、其次是谁；下面接"要守住结论：…" |
| 边界 | **可信** | 同一现价 DCF +16.8% / 相对法 0.0%，两法差 14.4 点 → 估值给不出方向 |

四行里只有"方向"带橙色竖线与浅底——这一块是唯一有结论句的地方，不能四行等重。

### 18.3 引擎新增三个字段（方向的数据基础）

| 字段 | 内容 | 样例 |
|---|---|---|
| `band` | 本桶区间 + 位置 + 三等分档位描述 | `{low:7.0, high:10.0, position:0.213, zone:"下沿"}` |
| `headroom` | 是否最高档、向上分界与差额 | `{at_top:true, ceiling:null, room:null, next_up:null}` |
| `distance_anchors` | distance ÷ 2.5 | `0.26` |

`zone` 的三等分刻意等分：任何更聪明的切点都需要依据，而这里没有依据可取，所以写成"纯位置描述"。

### 18.4 三个被自己发现并修掉的错

1. **"会推翻它的数据：季度机器人业务收入增速 ≥ 50%"——方向读反了**。
   `falsification[*].threshold` 存的是"逻辑**仍然成立**"的条件（≥50%、+0.3pp 以上），
   直接拼在"会推翻"后面等于说"增速 ≥50% 就会推翻"。改用 `maintain_conditions[*].condition` 原文
   （语义就是"全部成立才维持当前桶"），措辞改成"要守住结论：…（破一条即降一档）"。
2. **`3.30 + 3.10 + 1.23 = 7.64` 算不通**，实际是 7.63。分项各自四舍五入后相加必然差 ±0.01，
   所以符号从 `=` 改成 `≈`——这类"看起来算错了"的小数最容易被当成 bug 反复查。
3. **`R6_SCORE_BAND` 出现在两处**（顶部主标签 + 概览 chips），读者读不出是"按分数分桶"。
   统一走 `ruleCn()` 中文名，编号退进 `title` 供溯源。

## 19. 客户集中度的"上界"：把空着的一格说清楚（2026-10-25 十轮）

### 19.1 起点：一个"看起来像故障"的正常结果

有人问"药明康德最大客户收入占比没取到，是不是有问题"。实测 `annual_customer("603259")` 正常返回：
2025 年报（2026-03-24 披露，249 页，命中第 17 页），`form=total_only`、`five_ratio=48.11`、`top_ratio=null`。
全文检索 `最大客户 / 第一大客户 / 前十大客户 / 单一客户` 均 0 命中——**公司没披露单客户明细**，
准则只强制前五合计。所以不是取数故障，系统拒绝把 48.11% 当"最大一家"填进去也是对的
（`risk.customer_conc` 分档 30–50% 判"中"，真值可能是 12%）。

### 19.2 但两处确实该改

**其一，缺口说明把人往错的方向推。** 旧文案结尾是"需要读一次年报填单客户口径"——
读了也没有，等于把"披露缺失"说成"我们没读"。现已改为"这只上界不是点估计，故留空不填"，
并补上"即便按上界算，该项最坏也只落 X 档 Y 分"。

**其二，同页有一条更硬的证据没解析。** 药明康德第 17 页 B 段原文：
> B.报告期内向单个客户的销售比例超过总额的 50%、前 5 名客户中存在新增客户的或严重依赖于少数客户的情形 □适用 √不适用

公司勾"不适用"= 三者皆无 = **单个客户占比未超 50%**，且自认无严重依赖少数客户。
这是一条准则强制勾选的定性披露，此前完全没用上。现已解析：`single_50_check ∈ {not_applicable, applicable, None}`。

### 19.3 规则：上界可以收紧，但永不升格

| 证据 | 得到什么 | 能不能进评分 |
|---|---|---|
| 单客户明细（表 / 文字段） | 点值 | **能**（L1 观测值） |
| 只有前五合计 | 上界 = 合计 | 不能 |
| B 段勾"不适用" | 上界 = min(合计, 50%) | 不能 |
| B 段勾"适用" | 只说"三者中至少一件成立"，无数字 | 不能 |
| 没读到 B 段 | 什么都不知道 | 不能 |

上界还顺带给出一个真正有用的判断：**该项最坏落在哪一档**。药明康德上界 48.11% → 中档 5.0 分，
意味着这个缺口最多让风险维度掉档一次；若上界被勾选压到 50%，最坏是"弱"档 2.5 分。
`upper_bound_pct / upper_bound_band / upper_bound_score` 三个字段随 `fill.customer_annual` 出去，
评分卡风险维度那一行直接显示（`上界已知：… · 最坏「中」档 5.0 分`），不必去缺口面板里翻。

### 19.4 解析上的四个坑（都钉了单测）

1. **不能默认"没读到 = 不适用"**。扫描件常丢勾选字符，两个框都是 `□` 时必须返回 `None`。
2. **不能去隔壁借答案**。B 段后面紧跟"单个供应商…□适用 √不适用"，B 段自己的框丢了就截断，
   否则会把供应商的"不适用"读成客户的。
3. **"适用"不等于知道数**。它只说明前五名中有新增客户或存在依赖少数客户，正文没量化就仍是未知。
4. **上界是 min 不是抄**。合计 62% + 勾"不适用" → 上界 50%；两个数都要说，否则读者以为上界还是 62%。

### 19.5 影响与边界

`customer_conc` 在风险维内权重 0.3、风险维中线权重 0.08 → 综合分影响约 0.07，不改分桶；
风险维不在 `DATA_GATE_DIMS`，缺口不触发 R8；覆盖率按维度算，也不触发 R7。
所以这次不修分、只修**读法**：一个空格子从"没人管"变成"已知上界 48.11%，最坏中档"。

## 20. 阳光电源：这次真是解析 bug——供应商表被当成客户表接上了（2026-10-25 十一轮）

### 20.1 现象与第一层误判

"阳光电源（300274）最大客户收入占比没取到，是不是有问题"。按上一轮药明康德的路径先怀疑披露口径，
但实测返回的是第三种状态：

```
form=table_inconsistent  top_ratio=null  five_ratio=16.96  rows=5
cross_check: sum_ratio=25.11  total_ratio=16.96  ok=false  rule=sum==total
```

`rows=5` 说明表格抽出了五行，`quote` 里也确实躺着"1 Algihaz Contracting Company 4,010,035,531.92 4.50%"。
但五行之和 25.11 对不上合计 16.96。翻原年报第 36 页：客户五行占比是
4.50+3.51+3.40+2.89+2.66 = **16.96**，与合计严丝合缝。也就是说，**表没问题，是解析器算错了和**。

25.11 从哪来？恰好是下一页供应商表五行的和：14.59+2.83+2.60+2.55+2.54 = 25.11。差 0.01 是巧合。

### 20.2 根因：一个字符的长度，撞穿两道约束

`_ROW` 的名称列上限是 `.{1,24}?`，而 `Algihaz Contracting Company` 是 26 字符——**第 1 行整行匹配失败**。
接下来的循环用的是：

```python
if no != len(rows) + 1:
    continue      # ← 这里
```

第 2/3/4 行 no=2/3/4 全部被跳过；再往后就是供应商表的"1 供应商一 … 14.59%"，
`no=1 == len(rows)+1` 成立 → 供应商被当成客户接上了，一直数到 5 行 `break`。
合计仍取客户表的 `_TOTAL_ROW`（seg 里第一个"合计"），于是 sum=25.11 撞 total=16.96 → `table_inconsistent`。

**这不是"少一个数"，而是"可能静默填错值"**：本例里 `_TOTAL_ROW` 恰好先命中客户合计，把错误拦住了；
若客户表跨页导致其合计落在窗口外，`_TOTAL_ROW` 会取到供应商合计 25.12，与 25.11 只差 0.01（容差 0.06 内），
校验**直接通过**——`risk.customer_conc` 会拿到 14.59%（供应商第一大），判"优"档，看起来毫无异常。

### 20.3 三道修法

| 改动 | 位置 | 作用 |
|---|---|---|
| 名称列上限 24 → 40 | `_ROW` | 英文全称（26 字符起）不再漏行；漏第 1 行正是串表的起点 |
| 序号断档 `continue` → `break` | `_parse_table` | 断档即收手，绝不跳过继续找；缺失行后面本来也用不上 |
| 解析窗口在供应商锚点截断 | `_STOP_TABLE` | 第二道锁；截断后若无序号 1 则反向恢复（客户表排在供应商之后的情形） |

改完实测：

```
form=table  top_ratio=4.5  top_name=Algihaz Contracting Company  rows=5
cross_check: sum_ratio=16.96  total_ratio=16.96  ok=true
```

`single_50_check` 仍为 `null`——这份年报正文里没有 B 段那段勾选（全篇检索"单个客户"只命中附注的
重要性标准），按上一轮定的规则：**没读到就一个字都不许加**，不默认"不适用"。

### 20.4 影响与全量回归

13 份缓存年报重跑，12 份结果逐一不变（宁德 13.73 / 海康 / 格力 / 金山 / 长盈 / 创世纪 / 先导 …），
只有阳光电源从 `table_inconsistent` 变成 `table`。

对评分：`customer_concentration` 由缺失变成 4.5%（<15% → "优"档 10.0 分），
中线综合分 6.78 → 6.84（+0.06），分桶仍是【观察】（5.0–7.0），短线 5.84 → 5.92；
风险维覆盖率 0.7 → 1.0，置信度 0.769 → 0.772。**分数变化不改结论**，这次修的是读法。


## 21. 立场句：读者的第一个问题不是"几分"，是"该不该动手"（2026-10-25 十二轮）

### 21.1 反馈与原样

> "阳光电源 结论与置信度：方向、盯谁、可信，看了后还是不知道该不该买或者规避，普通人无法有效解读信息"

上一轮（§18）已经把机制语言改成了决策语言，四行是「结论 / 方向 / 盯谁 / 可信」。
拿阳光电源的真实渲染读一遍，问题不在措辞，在**角色**：

| 行 | 实际内容 | 读者要的 |
|---|---|---|
| 结论 | `观察 · 6.84 分 · 桶内 95%（上沿）`，下面接三层拆解与规则理由 | 我现在该做什么 |
| 方向 | "往下 3.34 分就落到【回避】；往上还差 0.16 分才够【入池】" | 同上 |
| 盯谁 | "单维归零也不改变分桶，不存在单点失效" | 同上 |
| 可信 | "两法差 14.4 个点…判断层占 44%" | 这份判断能不能信 |

四行的主语都是**分数与维度**，没有一行出现"你"。而"观察"这个词在框架里是"不够格"，在读者眼里
只是"看着"——他读完仍然不知道这意味着"别动"还是"再等等"。

### 21.2 改法：引擎给一句立场，界面把它放到第一屏

新增 `conclusion.stance`（`engine._stance`），四档与四个桶一一对应：

| 桶 | label | headline（真实渲染） |
|---|---|---|
| 观察 | **暂不介入** | 6.84 分，离「入池」还差 0.16 分——现在不是动手的位置 |
| 入池 | **够格研究** | 7.64 分，够格进入候选池 |
| 回避 | **按框架规避** | 3.10 分，已跌破 3.5 的回避线 |
| 人工复核 | **本框架不下结论** | 这套尺子量不出来：这套估值口径不适用它 |

配套三句固定回答：`do_next`（下一步做什么，1–3 条动词句）、`abandon`（什么情况下必须重看，
带证伪条件编号）、`caveat`（能力边界）。

界面同步重排：立场卡从右栏第三行提到**最上面、横跨全宽**，标题直接叫「现在该不该动手」；
原来的四行折进「进阶读数」——它们是给要看分数结构的人用的，不该挡住第一个问题。
正文限宽 820px，避免全宽卡片里一行 90 字。

### 21.3 三处必须说透的话

1. **"分数不会因为股价下跌自己变高"**。这是对这套分数最常见的误读——6.84 距离 7.0 只差 0.16，
   读者很自然会想"跌一跌就够了"。但分数衡量的是公司质量与估值，不是涨跌空间。
2. **"入池 ≠ 现在买"**。入池档如果只写"够格进入候选池"，会被直接读成买入信号。
   `basis` 里写死"只说明值得花时间研究透，不包含价格合适或马上会涨"。
3. **"人工复核 ≠ 这票很差"**。这一档最容易被误解，写成"这套尺子量不出来"并点明是哪条闸门
   （银行没有可比估值口径 / 数据覆盖不足 / 分数高但单维过低）。

以及 `caveat` 里那句绕不开的实话：**本框架没有回测样本，算不出涨跌概率，所以这里不会给出
「买什么卖什么」或「值多少钱」**。不写这句，用户会觉得系统在打太极；写清了，才知道该拿它做什么用。

### 21.4 边界：没有越界

立场句放在引擎而不是前端（前端各拼一句 = 同一份报告在不同视图里说不同的话，§16.1 的老问题），

（`wording.enforce_report` 已扫全段），因为这是全文最像投资建议的地方，反而最需要闸门。

> 1 客户1 87,786,831.84 3.58% ｜ 2 客户2 2.82% ｜ 3 客户3 1.94% ｜ 4 客户4 1.62% ｜ 5 客户5 1.45%

分母自洽：87,786,832 ÷ 3.58% ≈ 24.52 亿元，与 2025 年报口径吻合。客户名被匿名成「客户1–客户5」，
是公司自己的写法，不是解析丢了名字。5 家合计仅 11.40%——**爱美客的客户极度分散**，这本身就是结论，
不是"没披露"。

### 22.2 为什么他看到的可能是空的

缓存时间戳给出了线索：这份年报 PDF 落在 **06:48:14**，而全文文本缓存直到 **06:49:46** 才生成
（250 页、pypdf 抽取实测 19.1 秒）。也就是说他那一次请求停在"下载完、还没抽完"这一段——
服务进程 06:03 就在跑，不是重启杀的，属于运行中断。冷启动路径实测 20.3 秒可以走通，
重跑一次就有值（PDF 已缓存，不必重新下载）。

**但这暴露出真问题**：那一次空着时，报告写的是

```
company.customer_concentration | 未提供（该指标按缺失处理，不补零）
```

与"用户压根没填"一字不差。三种完全不同的空共用一句话：

| 实际情况 | 读者该做什么 | 当时的提示 |
|---|---|---|
| 只披露前五合计（药明康德） | 翻年报，接受上界 | 同上一句 |
| 年报没这项（银行/保险） | 接受缺失 | 同上一句 |
| 自动提取失败（本次） | **重跑一次** | 同上一句 |

于是每次遇到空格，他都得回来问一句"是否问题"——十三轮里问了三遍，其中两遍真的是 bug、
一遍是披露缺失、这一遍是运行中断。**问题不在数据，在报告不肯说清是哪种空。**

### 22.3 改法：让"空"带着原因走到报告里

```
取数层  raw.customer_error ← SourceError 的原文（不再只进 warnings）
装配层  _customer_gap_why() 三种空 → 三句话
       → input.data_notes["company.customer_concentration"]
引擎层  compute_dq(..., field_notes=) 用装配层的原因覆盖通用句（其余字段不受影响）
报告层  MD 前 10 条截断规则不吞"带原因"的条目
界面层  数据质量页的缺口栏渲染 field + reason
```

失败时现在写的是：

> 本次自动提取失败：年报 PDF 下载超时（30s）。已下载的年报会缓存复用，重跑一次通常能过；
> 同一条错误反复出现再人工读原文补录

只披露合计时写的是上界与最坏档位（药明康德：48.11% → 最坏「中」档 5.0 分），值仍留空。

### 22.4 顺带修掉一个界面 bug

界面「数据质量」页的缺口栏一直把缺口对象直接塞进 `esc()`：

```js
${d.gaps.map(g=>`<div class="tiny muted">· ${esc(g)}</div>`).join("")}
```

`esc` 是 `String(v)`，于是整栏渲染成 `· [object Object]`——**恰好是"为什么空"的解释入口坏了**。
改成 `<code>${esc(g.field)}</code> ${esc(g.reason)}`。概览卡上的「数据缺口 N 项」tooltip 早就读的
是 `g.field`，只有这一处漏了。

```
pytest                 280 passed（+3：失败原因带重跑指引、只披露合计给上界与档位、有值不留说明）
acceptance.py          33/33 PASS（A33 缺口原因可分辨）
build_ui --check        web/index.html 152 KB
```

### 22.5 边界

这次没有改任何评分口径，也没有为了让数字好看去动解析：值就是 3.58%，优档 10 分。
`single_50_check` 仍为 `null`——爱美客年报第 24 页只有「主要客户其他情况说明 □适用 ☑不适用」，
没有那句"向单个客户的销售比例超过总额的 50%"，按"没读到就不许加"的规则留空，不是漏读。

顺带确认一次口径：爱美客这份报告整体是**人工复核**（判断层覆盖 47.6% < 60%，触发 R7_COVERAGE），
原因是行业层五个指标全缺——中登质押表无该标的记录，行业归属与质押比例都取不到。
"不下结论"是行业层缺证据，与客户集中度这一项无关。
