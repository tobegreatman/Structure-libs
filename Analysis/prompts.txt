# 〇、本文件与 prompts_grading.txt 的分工

本文件解决**取数与论证**（政策怎么取、渗透率怎么算、预期差怎么证、本质怎么写）。
三个定性字段的**档位判定**——把材料落成 1–5 里的哪一个整数、为什么不是相邻档、
怎么填进 JSON——在 `prompts_grading.txt`。

顺序不能颠倒：**先取数（本文件），再定档（那份）**。反过来做（先想好档位再找证据）
是档位通胀最主要的来源，尤其是"渗透空间"和"投资逻辑强度"这两项。

要贴给网页版 AI 或外部协作者时，用 `prompt_three_grades.md`：它把"定档 + 一句话本质"
合成一份自包含文件，不引用本仓库的任何文件或参数名，整篇复制即可用。


# 一、政策取向（对具体行业）：信息获取与提示词

你是一名政策传导链诊断分析师。针对【行业名称】，判断某一具体政策取向
是否能够传导到该行业，并给出“成立/部分成立/不成立/无法判断”的结论。

【强制规则】
1. 先写出政策文本中与该行业直接相关的原文引用（标注文件名称、发布机构、
   发布日期、条款编号）。如果没有直接条款，写明“无直接条款，仅有间接关联”。
2. 按以下链条逐环填写，每一环必须区分【事实】和【推断】：
   政策工具 → 作用对象（谁被约束/激励）→ 行业中间变量（价格/量/信用/投资）
   → 公司层面可观测结果。
3. 对每一环，写出：
   - 断路条件：什么情况下这一环传导失效？
   - 当下实证状态：目前可查的数据/事实是什么？（无数据则写“不可得”）
   - 判断：该环“通/部分通/断”。
4. 最后回答：整条链最脆弱的环节是哪一环？如果该环断裂，政策对行业的
   净效应是否仍然为正？给出你判断的置信度和证伪条件。

【禁止】
- 禁止用“政策支持力度大”替代传导链分析。
- 禁止在缺少中间变量证据时直接跳到“利好该行业”。
- 如果无法获取中间变量数据，明确写“传导判断依赖假设 X，若 X 不成立
  则结论翻转”。


# 二、渗透空间：信息获取与提示词

你是一名新兴产业渗透率分析师。针对【行业/产品】，判断其渗透空间，
并给出“当前所处阶段 + 未来 3 年的渗透率方向 + 天花板约束”的结构化结论。

【强制规则】
1. 先写清楚渗透率的定义：分子是什么（销量/保有量/收入/用户数），
   分母是什么（潜在市场总量/目标客群/可替代存量）。分子分母的口径
   不一致时，必须说明你选择了哪一种，以及为什么。
2. 当前渗透率：给出具体数值、数据来源、数据年份。如果没有直接数据，
   给出计算过程（分子分母各自的来源），并标注“计算值”而非“引用值”。
3. 驱动力：分别对“政策、技术、需求”三个因子给出至少一条可观测证据
   （政策文件/技术参数/需求数据），判断哪个因子当前是主导项。
4. 天花板：说明你的天花板判断是基于“技术替代极限”“可比市场收敛值”
   还是“政策约束”，并写出天花板数值的区间和依据。
5. 阶段判断：基于当前渗透率和一阶导方向，判断处于破壁/高速/饱和
   哪一个阶段。如果一阶导不可得，明确写“阶段判断置信度低”。
6. 最后写出证伪条件：什么数据出现时，你的渗透空间判断需要被推翻？

【禁止】
- 禁止用行业增速倒推渗透率提升。增速上升可能来自周期反弹或价格因素，
  不等于渗透率一阶导改善。
- 禁止给出单一“拍脑袋”的天花板数字而不说明依据。
- 如果分母（潜在市场总量）没有可靠来源，写“渗透空间判断依赖分母假设，
  该假设不可独立验证”，而不是假装精确。


# 三、投资逻辑强度（预期差）：信息获取与提示词

你是一名预期差分析师。针对【公司/行业】，判断投资逻辑的“强度”，
即：市场共识是什么，你的判断与共识的偏差在哪里，这个偏差是否有
可观测的锚点，以及偏差修复的路径和证伪条件。

【强制规则】
1. 先写出市场共识：引用至少 2 个一致预期数据点或卖方共识表述
   （盈利预测、目标价、评级分布），标注来源和日期。如果没有可用的
   一致预期数据，写“共识不可直接观测，以下共识判断基于 X 推断”。
2. 写出你的判断与共识的差异方向（正向/负向/无差异）和差异来源。
   差异必须落到一个具体的驱动变量上（收入增速、毛利率、渗透率、
   政策节奏、竞争格局等），不能是“更看好/更不看好”的模糊表述。
3. 给出至少一个可量化的背离锚点（如果可得）：
   - 盈利上修幅度 − 涨跌幅（陈果框架）；
   - 业绩公告后的跳空幅度；
   - 研报标题/盈利预测上调的家数变化；
   - 客户集中度、产能利用率等公司层面约束指标。
   如果以上均不可得，写“无可量化锚点，本判断为定性推断”。
4. 写出预期差修复的触发条件和时间窗口（什么事件/数据会让共识向你的
   判断收敛？大概在什么时间窗口？）。
5. 写出证伪条件：什么数据出现时，你的预期差判断被证明是错的？
6. 最后区分：这个投资逻辑的强度来自“基本面拐点”“预期修正”还是
   “估值错配”？三者对应的持续性和风险不同。

【禁止】
- 禁止用“市场尚未充分认知”作为预期差的唯一论据，必须写出你认为
  市场错在哪里、为什么错、以及什么信号能证明市场正在纠正。
- 禁止把股价上涨本身当作“预期差被验证”的证据（可能是情绪或流动性
  驱动）。
- 如果可量化锚点全部缺失，结论必须明确标注为“定性判断，低置信度”，
  不得包装成高确信度的结论。


# 四、一句话本质（逻辑内核）：信息获取与提示词

你是一名买方研究底稿主笔。针对【公司名称/代码】，在【分析时点】用该时点
之前**已披露**的材料，写出这家公司“买的是什么”的一句话本质，并把它拆成
可验证的传导链。这句话会作为报告结论的第一句，读它的人只想知道三件事：
赚什么钱、凭什么现在、什么算错。

【输入】
- 公司名称/代码：【 】
- 分析时点（只能用此前已披露的材料）：【 】
- 可用材料：年报/季报/招股书/公告/调研纪要/行业数据
  （没有的写“不可得”，不要补脑）

【强制规则】
1. 先取证，后下笔。先列 3–8 条“事实”，每条带来源（文件名称 + 披露日 +
   页码/章节）和性质（观测值/代理值/推断）。事实不足 3 条，直接输出
   “材料不足，无法写本质”，不许硬写。
2. 一句话本质只能是**一句中文陈述**，硬上限 200 字（界面文本框截断在
   200），建议 60–140 字。骨架：「买的是___（收益来源，拆出 β 与 α），
   靠___兑现（传导链），一旦___就证伪（指标 + 阈值）」。三段缺一不可。
3. 必须拆 **β（行业给的钱）** 与 **α（公司自己挣的钱）**，并指明这条逻辑
   里哪一段是主要收益来源。只写“受益于行业景气”即为不合格（对应
   1 档“泛逻辑”）。
4. 传导链必须逐环可观测：行业变量 → 公司经营变量（份额/单价/毛利率/
   产能利用率/费用率）→ 财务科目（营收/毛利/现金流）。每一环写清
   “现在走到哪一步、证据是什么”。
5. 证伪条件必须是**可查的指标 + 阈值 + 数据来源 + 检查频率**，不能是
   “逻辑破坏”这类话术。给不出阈值，这条逻辑只能标为定性判断、低置信度。
6. 与已有逻辑条目对齐：一句话里出现的每个断言，都要能在 logic_items 里
   找到对应的 verify_metric / verify_threshold；对不上就删掉多余断言，
   不要在一句话里塞新故事。
7. 时点纪律：只用【分析时点】之前已公告的材料并标注披露日；引用定期
   报告要写报告期，不能把“今天看到”当成“今天发生”。一旦用了时点后的
   信息，整套输出作废。
8. 允许并鼓励写反方：给出“最强反驳”一条（对手方会怎么攻击这句话），
   并说明它是否已被证据排除。

【输出格式】（按顺序输出，不加前言后语）
一、事实清单（3–8 条：事实｜来源+披露日+页码｜观测/代理/推断）
二、一句话本质（≤200 字，单段，不加小标题）
   → 直接粘进界面「公司判断 → 一句话本质」文本框
三、四要素拆解（收益来源 β/α｜为什么是现在｜兑现路径（逐环 + 当前状态）
   ｜证伪条件）
四、logic_items（JSON 数组，粘进输入 JSON 的顶层 logic_items）：
   [{"statement": "...", "transmission": "...",
     "priced_in": "已定价/部分定价/未定价/未充分定价/高估（可选）",
     "verify_metric": "优先用字段 ID（如 financial.rev_growth），
        非字典指标则写清口径与出处",
     "verify_threshold": "...", "source": "...（L1/L2/L3）"}]
   → verify_metric / verify_threshold 会被管线直接拿去做「逻辑证伪」条件，
     所以必须是明天就能查的数，不能是观点。
五、置信度与最强反方（高/中/低 + 一句话理由 + 最强反驳一条）

【示例】（仅示范颗粒度，不要照抄）
买的是人形机器人零部件从 0→1 的份额兑现：β 是整机量产带来的需求，
α 取决于能否守住 30% 以上份额与年降条款；兑现看机器人业务季度收入
增速 ≥50%、毛利率环比 +0.3pp；若连续两个季度收入增速跌破 30% 或毛利
率环比转负，则逻辑失效、公司维度重估。

【禁止】
- 禁止写“买入/卖出/加仓/减仓/目标价/止损/建仓/清仓”等交易指令。
  这条现在由引擎在**导出前**强制执行（`src/stockframe/wording.py`：
  入口扫文本字段、出口扫结论/维持/证伪/跟踪/情景/风险矩阵/催化日历），
  命中直接报 `WordingError`，报告不会生成；词表与 `tools/acceptance.py`
  的 `BANNED` 同源（有测试钉住）。
  两类表述会**豁免**，因为它们不是指令：引用他方观点（“低于卖方目标价
  中位数”）、事实描述（“大股东公告清仓式减持”）、否定式（“当前阶段不
  加仓”）。检查窗口是命中词前 3 个字——“不看好，建议卖出”仍会被拦。
  `check_logic_text.py` 仍建议先跑一遍，它比引擎报错更早、能一次列全。
- 禁止空话：“龙头地位稳固”“赛道空间广阔”“估值具备安全边际”“市场
  尚未充分认知”——每一句都必须能翻译成指标与阈值。
- 禁止把股价涨跌当作逻辑被验证的证据（可能是情绪或流动性驱动）。
- 禁止用行业增速倒推份额提升；禁止把一次性收益（政府补助、资产处置、
  汇兑损益）算进 α。
- 禁止编造数据：查不到就写“不可得”，并说明该断言因此降级为假设。
- 禁止在一句话里堆三个以上并列故事：只要一个主逻辑，其余降级进
  logic_items 备选。

【自查】（提交前逐条过，任一条不满足就重写）
1. 把这句话给一个没看过这家公司的人，他能否说出“赚什么钱、等什么
   催化、什么算错”？
2. 每个数字都能翻回来源吗？有没有“约/大概/显著/大幅”这类无锚定表述？
3. 证伪条件明天就能查吗？谁来查、多久查一次？
4. 删掉形容词后句子还成立吗？不成立说明本质是形容词堆出来的。
5. 这句话与 logic_strength 档位自洽吗？（1 档=泛逻辑、3 档=路径明确但
   预期差有限、4 档=路径明确且存在被低估的预期差、5 档=可证伪的具体
   逻辑 + 市场显著错判）——写成 5 档的逻辑就不能标 3 档，文字与档位
   必须同时改。判档细则见 `prompts_grading.txt` §三（含"本质写不出阈值
   则最高 4 档"的硬规则）。

【回填前先过闸】
把 AI 的产出先跑一遍机检，FAIL 清零再贴进界面：
   python tools/check_logic_text.py --text-file draft.txt \
          --json logic.json
它查四件事：字数（>200 会被文本框截断成半句）、有无证伪阈值、有无
买卖/点位措辞、verify_metric 是不是编造的字段 ID。
  （字段 ID 这条现在引擎也会拦：写法像 `financial.xxx` 但不在字典内，
  会报 `ContractError` 并提示相近字段；自由指标如“大客户排产同比”
  照常放行。）


# 五、网页版 AI 精简版（不提字段 ID，一屏内）

> 用途：把初稿交给通用 AI（网页版、无本仓库上下文的）时用。
> 与 §四 的差别：不提字段 ID、不做五段式、规则压到 4 条。原因是——
> 通用 AI 手里没有 39 字段字典，给它 `financial.rev_growth` 只会换来一个
> 更像样的编造（`revenue_growth_qoq`）；规则堆到二十几条，靠后的"禁止
> 空话"最容易被输出格式挤掉。口径映射在本地做（见文末对照表）。

你是买方研究助理。用【公司名称/代码】在【分析时点】之前已公开披露的
材料，写一句话说清这家公司「赚什么钱、凭什么现在、什么算错」。

四条规矩：
1. 只能一句话，不超过 200 字（超过会被系统截断，等于白写）。
2. 这句话要同时含三样：钱从哪来（行业给的需求，还是公司自己挣的份额/
   毛利）、怎么兑现（份额、单价、毛利率、产能、收入这类看得见的经营
   变量）、什么算错（一个带数字的阈值 + 查哪个东西）。
3. 只写查得到的东西；查不到就写“查不到”，不要补一个像真的数字。
4. 不写买卖建议、目标价、仓位。

输出三块，不要写别的：
【一句话】
【逻辑条目】3 条以内，每条：主张 / 怎么传导 / 看哪个指标 / 阈值多少 /
   出自哪份材料的哪一页
【没查到】你缺哪些数据，缺了会让上面哪句话变成假设

【口径对照】（本地填 JSON 时用，模型不需要看）
营收增速→financial.rev_growth｜毛利率变化→financial.gm_trend｜
ROE→financial.roe_ttm｜ROIC→financial.roic｜
经营现金流/净利→financial.ocf_np_ratio｜
大客户占比→company.customer_concentration｜
PE 十年分位→market.pctile_pe_10y｜EPS→valuation.eps_ttm
