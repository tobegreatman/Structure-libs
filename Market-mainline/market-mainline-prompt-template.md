# 市场主线判断 · AI 联网分析提示词模板

> 版本 v3.8 · 2026-10-28 ｜ 配套《从认知到体系》第 7 章环境态三态表、第 9 章「三过滤第一关·主线」
> 用途：将提示词整段复制给具备联网能力的 AI/Agent，由其自动获取真实数据、按科学框架判断 A 股市场主线，输出**标准 JSON**。
> 呈现：JSON 有两条路——① 粘贴进本目录可视化报告页 `market-mainline-report.html` 自动渲染；② 配合第五节「报告生成提示词」，让 Agent 从零生成苹果风单文件 HTML 报告。
> 定位：补上体系中「机器筛不出、人工最难做」的最后一环——主线与环境态的初判。

## 一、设计原理（为什么这样设计）

**主线 ≠ 单日最强板块。** 主线 = 在足够长窗口内持续吸纳资金、持续产生赚钱效应、且有可延续逻辑支撑的方向。

判断的科学性来自四层防御：

| 层 | 机制 | 防住的错误 |
|---|---|---|
| 三时间窗口 | 日线跟踪 / 周线确认 / 月线定位，交叉验证 | 把单日脉冲、一日游题材当成主线 |
| 四维评分卡 | 价格、资金、赚钱效应、逻辑各 0-2 分，打分标准逐条写死 | 「强/中/弱」凭感觉拍脑袋，结论无法复核 |
| 单日脉冲冷却 | 首次爆发方向强制进入候选池冷却，连续 2 日以上强势才可升级 | 单日大涨就宣布新主线 |
| 置信度分级 + 数据缺口降档 | 主线 / 候补 / 轮动三档结论；缺数据自动降置信 | 证据不足时硬下结论 |

核心纪律一句话：**单一交易日的数据只能更新状态，永远不能形成或推翻结论；结论只能由 20-60 日窗口内的持续性证据产生，且每个结论都能拆回具体的分数与来源。**

### v3.0 相对 v2.0 的升级点

1. 数据层：新增**数据质量四级分级**（A 逐日序列 / B 区间快照 / C 二手汇总 / D 缺口），关键数字要求**双源交叉验证**；
2. 分析层：四维证据从「强/中/弱」定性改为 **0-2 分量化评分卡**，主线确认有了明确的分数线；
3. 纪律层：新增**单日脉冲冷却规则**，从机制上杜绝「单日强势定主线」；
4. 呈现层：新增第五节 **JSON → 苹果风 HTML 报告生成提示词**，任何具备代码能力的 Agent 都能把台账 JSON 渲染成图文并茂的单文件报告；
5. JSON Schema 与 v2.0 **完全兼容**，旧报告页照常可用，仅新增可选 `score` 字段。

### v3.1 修订（2026-10-15，源自首次实战核查）

v3.0 首次实战（week-10-15）核查发现 6 处模板漏洞 + 4 处执行失控，本版针对性打补丁：

1. **联动校验入红线**：meta.verdict 与 candidates 分数强制挂钩——存在 score ≥4 候补时禁止「无主线·轮动市」；
2. **上期对账机制**：完整版运行须附带上期 JSON，prev 值优先引用上期台账；距上期 <5 个交易日且结论变档时，必须逐条列窗口级推翻依据；
3. **自查改强制演算**：新增 selfCheck 字段，逐 candidate 写出 d1+d2+d3+d4=score 算式才可输出；
4. **Schema 枚举约束**：vsMA20/vsMA60 限「上方/下方/附近/null」；ladder 限单方向梯队；relativeStrength 须注明跟踪对象与口径；
5. **数据截止时点**：周度完整版必须用收盘后数据，盘中快照须标注且置信度降一档。

### v3.2 修订（2026-10-15，轻量版完善）

对照 v3.1 补丁复查轻量版，修复 2 处漏洞 + 4 处一致性问题：

1. **跨日状态传递（修漏洞）**：新增输入区「附昨日快报 JSON」——「连续第 2 日」切换预警与冷却期计数此前因 AI 无状态实际无法执行；未附带时冷却从第 1 日起算并注明；
2. **取数补市场广度（修漏洞）**：原清单漏了环境态核心指标（上涨家数占比），却要求「对照环境态」给操作提示；同步补 v1.1 的「破 35%/55% 标环境态或变」联动；
3. **输出加 JSON 台账**：与每日复盘模板字段口径一致的精简对象，逐日归档，可直接作为周度完整版 W1 证据输入；
4. **prev 口径**：「较上日」数值优先引用昨日台账同字段；
5. **枚举约束同步**：vsMA20/vsMA60 限「上方/下方/附近」；
6. **情绪周期标签**：补六选一标签（冰点/回暖/发酵/高潮/分歧/退潮），与每日模板口径对齐；
7. **分工写死**：有操作日 → 每日复盘模板 v1.1；无操作日/快速跟踪 → 轻量版；两者 JSON 可混入同一台账。

### v3.3 修订（2026-10-17，快检填法澄清，无规则变更）

对照 10-16 首次快检实战反馈，澄清 2 处填法歧义：

1. **switchAlert 无昨日台账时**：明确填字符串「无法判定：无昨日台账」——此前「无预警填 null」与快报第 4 项「无昨日台账时写无法判定」并存，实战中 AI 摇摆（10-16 台账误填 null，把降级说明挤入 statusUpdate，切换判定的跨日状态传递失效）；
2. **mainline.health 单选**：三选一禁止组合填法（实战出现「分歧/退潮信号」组合值，下游样式映射与周度对账无法解析）。

### v3.4 修订（2026-10-17，快检 Schema 扩展）

1. **新增可选字段 strongest**：`{name, attr}` 对应快报第 2 项「今日最强方向」——此前该信息仅存在于快报文本，JSON 无字段承载，取数成果无法归档，周度 W1 证据缺一环；attr 三选一（既有主线延续 / 高潮补涨 / 新候选），取不到填 null；日报页已同步渲染「今日最强」行，旧台账无此字段时自动跳过；
2. **呈现优化**：日报页数据缺口由胶囊芯片改为左竖线引述列表，适配 40+ 字长文本缺口说明。

### v3.5 修订（2026-10-24，证据链方向归属澄清）

复盘 week-10-15～10-23 台账发现：`ladder` 已明确单方向，但 `evidence` 未约束方向归属，AI 在多候选时追加重复维度块（如 week-10-23 出现两个 D3，第二个属人工智能/物理AI），而页面取「最后一条」导致四维雷达混用两个方向的标题与评级。本版修复：

1. **evidence 明确单方向四维链**：与 ladder 取同一方向；同一 dim 只允许一条，其余候选的证据写在其 candidate.note，禁止追加重复维度块；
2. **页面呈现配套**：章节增加「本节对象」标签（无主线时标注候选观察对象）；重复 dim 块移入「其他方向补充证据」，不参与四维评级与雷达；相对强度图例改用实际方向名。

### v3.6 修订（2026-10-28，均线字段反推断补丁）

week-10-28 台账核查发现新失控模式：AI 取不到沪深300 MA60 一手数值时，以「年内跌幅、价格显著低于中长期均线」等间接证据推断方向填入 vsMA60=「下方」，并自评 B 级——枚举约束防住了模糊词，没防住「推断值冒充足数结果」（间接推断不是区间快照，B 级评级同样被误用）。本版三层修复：

1. **均线优先自行计算（根治）**：MA20/MA60 无需单独搜索——P0 已强制取大盘指数近 60 日收盘序列，取到后直接以「最近 20/60 个收盘价算术平均」自行计算，source 写「依据 [来源｜日期] 收盘序列计算」，从源头消除「搜不到均线值」这一缺口；
2. **推断 ≠ 获取（Schema 红线）**：vsMA20/vsMA60 只能填来源实际给出、或依 P0 收盘序列计算的均线相对位置；以年内跌幅等间接证据推出的方向禁止填入枚举字段——间接依据只能写入 dataGaps 作旁证，字段本身填 null；
3. **评级口径澄清**：推断值不属于 B 级快照（B 级必须是来源实际给出的数据），一律视同 D 级缺口处理；轻量版第 ⑤ 项取数与每日复盘模板同步补计算口径与反推断约束。

### v3.7 修订（2026-10-28，序列获取路径与派生指标自算泛化）

week-10-28 台账暴露 v3.6 同族问题的更大面：板块指数 MA20/MA60、D1 跑赢天数占比、relativeStrength 曲线、ladder gain20d 全部依赖逐日序列，而序列靠网页搜索基本取不到（实战 AI 只拿到 10/27、10/28 两点快照，gain20d 全 null）；主力净流入出现四源分歧（证券之星 48.96 亿 / 东财概念口径 75.21 亿 / 证券时报 86.96 亿 / 约 103 亿），AI 跨口径混合后自创「保守区间 48.96—75 亿」。根因：akshare 接口提示只写在模板「使用说明」，未进入复制用的提示词正文——AI 看不到取数路径。本版把 v3.6 的「自算」从大盘均线泛化为系统规则：

1. **序列获取路径入正文**：逐日序列类数据优先走数据接口取序列后自算，常用接口写入第一步；板块近 60 日收盘序列一次取数、三处复用（D1 占比 / 板块均线 / 相对强度）；
2. **派生指标自算清单**：MA20/MA60（大盘+板块）、跑赢占比、gain20d、relativeStrength 一律基于已取序列自算，禁止以「搜索不到指标现值」记缺口；新股 gain20d 按「上市以来」口径注明，禁止轻易 null；
3. **资金流口径纪律**：多源分歧先核口径（概念/行业/成分股加总不可直接比较），以与板块涨幅排名同源的口径为准；各源方向一致时分歧只影响量级、不影响 D2 方向性评分；禁止自创区间值折中；
4. **降级代理与评分封顶**：无代码能力、序列确不可得时——D1 以区间涨幅代理（上限「中」）、D2 以近 5/10 日资金旁证（上限 1 分）、relativeStrength 按 5/20/60 日三点快照（禁止近 2 日两点冒充）；
5. **ladder 个股基础行情必取**：个股当日涨跌幅/成交额是最易得数据，逐只标注来源，禁止跳过。

### v3.8 修订（2026-10-28，模板工程化精炼：数据源瀑布、四段式结构与字段格式收口）

三个维度分三批次落地，规则语义零删减（v3.1~v3.7 全部约束等价保留）：

1. **数据源三级瀑布**：L1 数据接口直取 → L2 权威财经媒体 → L3 二手汇总（仅旁证，前两级均不可得才可引用）；取数清单推荐来源全部升级为「首选 → 备选」链并按实战校准（情绪面韭研公社居首、资金面证券时报居首、指数序列新浪接口居首）；接口清单固化——新浪 K线 HTTP 接口（实测稳定，附完整参数与 symbol 替换规则）、东财 K线（备选，注明部分环境被拦）、akshare（Python 环境）；明确「板块指数序列无稳定免鉴权接口，取不到属常态 → 直接降级，不反复尝试」。
2. **第一步四段式重组**：◇ 取数 → ◇ 计算 → ◇ 纪律 → ◇ 降级，开篇新增流程地图一行；红线 10/11 收敛为浓缩禁止项+指针（细节唯一出处归第一步）；纪律节按「时点 → 口径 → 分级」自然次序重排；全部交叉引用统一为「◇ 降级」节名。
3. **输出字段格式收口**：source 统一「来源｜日期」紧凑格式（30 字内），多源对比/口径说明/计算细节一律移入 dataGaps；volumeTrend 限短语；maxConBoards.theme 限题材名（梯队细节归 ladder/note）。Schema 字段结构不变，向后完全兼容。

## 二、使用说明

| 场景 | 模板 | 建议频率 |
|---|---|---|
| 周度主线定调 | 第三节 · 完整版 | 每周最后一个交易日收盘后（与体系「周日更新环境态」节奏对齐） |
| 每日状态跟踪 | 第四节 · 轻量版 | 快速跟踪，约 5 分钟；需要盘面三面解读与双源验证时改用《每日复盘模板》v2.0（盘面分析完整版），两者 JSON 字段兼容可混入同一台账 |
| 可视化呈现 · 路径 A | 报告页 `market-mainline-report.html` | 完整版分析后，把 JSON 导入报告页 |
| 可视化呈现 · 路径 B | 第五节 · 报告生成提示词 | 把 JSON + 提示词给 Agent，生成独立苹果风 HTML 报告（适合归档、分享） |

**执行方式**：整段复制提示词 → 粘贴给具备联网搜索能力的 AI（Trae / Claude / Kimi / ChatGPT 等）→ AI 输出「一句话结论 + JSON」→ 复制 JSON 走路径 A 或 B 呈现 → 对照第六节检查单人工复核。具备代码执行能力的 Agent 可用 akshare 等接口辅助取数（接口清单已写入第三节第一步「序列数据获取路径」）。**运行完整版时，把上一期完整版 JSON 台账一并粘贴（首期除外）——这是对账机制的输入，缺失时 AI 会在 dataGaps 登记。**

**关键预期**：模板的产出是「证据链 + 评分 + 分级结论」，不是「必涨预测」。当所有方向都不达标时，合法结论就是「当前无主线、轮动市」——这本身就是重要信息，防止硬凑。

**与每日复盘模板的关系**：日度模板（v2.0，盘面分析版）的 JSON 台账字段与本模板口径一致，近 5-7 日台账可直接作为本模板 W1 短窗证据输入；本模板的周度结论（主线 / 环境态 / 信号权限）反过来是日度模板输入区的必填项，形成闭环。

## 三、主提示词 · 周度完整版（整段复制）

```text
你是专业的 A 股市场主线分析师，具备联网搜索与网页阅读能力。你的任务：获取真实市场数据，用多时间窗口交叉验证与量化评分卡，判断当前市场主线，输出结构化报告。严格按以下五步执行。

输入附带：用户可能在提示词末尾附上「上期完整版 JSON 台账」。若附带，输出前必须执行第四步附的对账；若未附带，在 dataGaps 登记「无上期台账，对账跳过（首期或用户未提供）」。

流程地图：取数（第一步，四节：取数 → 计算 → 纪律 → 降级）→ 三窗口分析（第二步）→ 四维评分（第三步）→ 主线定档与对账（第四步）→ 输出 JSON（第五步）。

▍第一步 · 数据获取（全部联网完成，禁止用训练记忆里的行情填充）

◇ 取数 · 清单与来源优先级

按清单取数，每个数字必须标注 [来源｜日期]；取不到的项目写入「数据缺口」，禁止编造。

数据源三级瀑布（每项数据按此顺序取数）：
- L1 数据接口：具备代码执行能力时优先直连接口取原始序列/快照（HTTP 接口与 akshare 函数见「序列数据获取路径」）——最稳定，且可直接自算派生指标；
- L2 权威财经媒体：财联社、证券时报、证券日报、东方财富、同花顺、新浪财经的原创报道与行情页面；
- L3 二手汇总：自媒体、微博、头条号转引——仅作旁证与交叉验证，L1/L2 均不可得时才可引用并注明「二手」。

关键数字（涨停家数、主力资金流向、炸板率）须尽量双源交叉验证，两源差异大时以行情软件原始数据为准并注明分歧：

| 优先级 | 数据 | 窗口 | 推荐来源（首选 → 备选） |
|---|---|---|---|
| P0 | 行业与概念板块涨跌幅排名（逐日序列，不是只有当日快照） | 近 60 交易日 | 当日排名：东方财富行情中心 → 同花顺；逐日序列：靠接口取（板块序列接口可达性差，取不到直接走降级代理） |
| P0 | 大盘指数日线（上证指数、沪深300，含成交额） | 近 60 交易日 | 新浪财经 K线接口（稳定，见取数路径）→ 东方财富行情 |
| P1 | 板块成交额及其占全市场比重的变化 | 近 20 交易日 | 东方财富数据中心 → 证券时报/新浪财经资金面报道 |
| P1 | 板块主力资金净流入（累计值） | 近 20 交易日 | 证券时报·资金面 → 证券之星 → 东方财富·资金流向、同花顺资金（多源口径差异见「资金流口径纪律」） |
| P1 | 涨停家数、连板梯队（最高连板/晋级率）、炸板率 | 近 10 交易日 | 韭研公社 → 财联社复盘 → 开盘啦、同花顺 |
| P2 | 候选板块龙头股：板块内流通市值前 20% 且日均成交额前 10% 的标的，近 20 日涨幅、是否创新高 | 近 20 交易日 | 新浪 K线接口自算近 20 日涨幅 → 行情网站快照 |
| P2 | 政策文件、产业事件、券商策略观点（取标题与核心逻辑） | 近 2 周 | 官方网站 → 财联社 → 券商研报摘要 |
| P3 | 市场融资余额变化 | 近 20 交易日 | 东方财富数据中心 → 可得时 |

◇ 计算 · 序列接口与派生指标自算

序列数据获取路径（强制）：跑赢天数占比、大盘与板块均线、relativeStrength 曲线、gain20d 全部依赖逐日收盘序列，此类序列靠网页搜索基本无法直接返回——禁止因「搜索不到指标现值」记缺口或填 null，优先走数据接口取序列后自算，网页搜索仅作交叉验证；无代码执行能力时按下方「◇ 降级」节处理。

接口清单（按环境可用性逐级尝试，稳定性为实测标注）：
- 新浪财经 K线接口（HTTP 直连，实测稳定，指数/个股通用）：money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData?symbol=sh000300&scale=240&ma=no&datalen=120 —— symbol 依此替换：sh000300（沪深300）/ sh000001（上证）/ sh600xxx / sz00xxxx（个股），scale=240 为日线，datalen 控制根数，返回日期与收盘价序列；
- 东方财富 K线接口（HTTP 直连，备选，部分环境被拦）：push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.000300&klt=101&lmt=120 —— secid：沪深300=1.000300、上证=1.000001、沪市个股=1.60xxxxx、深市个股=0.00xxxxx；
- akshare（Python 环境）：stock_zh_a_hist 取个股日线，stock_board_concept_hist_em / stock_board_industry_hist_em 取概念/行业板块指数日线，指数日线接口取沪深300。
注意：概念/行业板块指数序列无稳定免鉴权接口（东财板块接口常被拦），板块序列取不到属常态——直接按「◇ 降级」节处理，不要反复尝试浪费时间。板块指数近 60 日收盘序列（若取得）一次取数、三处复用：D1 跑赢占比、板块 MA20/MA60、relativeStrength 曲线。

派生指标自算口径（强制，替代搜索指标现值）：
- MA20/MA60（大盘与板块指数）：最近 20/60 个收盘价算术平均，source 写「依据 [来源｜日期] 收盘序列计算」；禁止以年内跌幅等间接证据推断均线相对位置；
- 跑赢天数占比（D1）：逐日比较板块与沪深300 涨幅统计得出；
- gain20d（ladder 个股）：依个股近 20 日收盘序列计算；上市不足 20 日的新股按「上市以来」口径并在 note 注明；自算与来源快照均不可得时才填 null，并把实际可得口径写进 note；
- relativeStrength：依板块与沪深300 收盘序列逐点计算近 60 日累计涨幅。

◇ 纪律 · 时点、口径与质量分级

数据截止时点（强制）：周度完整版必须使用收盘后数据；盘中快照只能标注「盘中」字样使用，且 meta.confidence 降一档、summary 注明「基于盘中数据，收盘后需复核」。禁止用盘中数据产出定调结论而不标注。

资金流口径纪律（多源分歧处理）：各源板块主力净流入口径不同（概念板块 / 行业板块 / 成分股加总），数值不可直接比较——取与板块涨幅排名同源的口径为准；同口径仍分歧超 20% 时以行情软件（东方财富/同花顺）原始数据为准。各源方向一致（如均为净流入）时，分歧只影响量级、不影响 D2 方向性评分，在 dataGaps 注明分歧幅度即可；禁止自创「区间值/保守值」折中（如混合两个口径的「48.96—75 亿」）。

数据质量分级（每项数据取数后自行定级，写入 dataGaps 或来源说明）：
- A 级：逐日序列完整 → 正常参与评分；
- B 级：只有「近5日/近20日/近60日」区间快照 → 可用，注明「序列降级」；
- C 级：二手汇总（自媒体转引、截图数据） → 只作旁证，不能单独支撑强评分；
- D 级：取不到 → 记缺口，对应维度评分上限锁 1 分。
整体降级规则：P0/P1 中出现 2 项及以上 C/D 级 → 总结论置信度自动降一档，并在 meta.summary 注明。
推断值不参与评级：由间接证据推出的数值（如以年内跌幅推断均线位置）不属于 B 级快照——B 级必须是来源实际给出的区间数据；推断值一律视同 D 级：字段填 null，推断依据写入 dataGaps 作旁证。依来源收盘序列计算的派生值（如 MA20/MA60）按其序列的原始等级定级，source 写「依据 [来源｜日期] 收盘序列计算」。

◇ 降级 · 代理指标与评分封顶（无代码执行能力、序列确不可得时）：D1 以「近 20 日区间累计涨幅 vs 沪深300」作代理——显著跑赢 → 最高「中」（占比口径无法验证，禁给强）；未跑赢 → 按弱评 0-1 分。D2 以「近 5/10 日主力净流入累计（板块资金流排行可得）+ 当日净流入」作旁证——净流入为正 → 最高 1 分；净流出 → 0 分。relativeStrength 快照降级必须按近 5/20/60 日三点口径（板块排行页周期切换可得），禁止以近 2 日两点冒充快照。ladder 个股当日涨跌幅/成交额/连板数为基础行情数据，逐只必取并标注来源，禁止因板块序列难取而跳过。

▍第二步 · 三窗口分析（时间粒度纪律）

- W1 短窗（近 5-10 交易日，日线粒度）：识别「新爆发方向」，只产生候选，不下结论。
- W2 中窗（近 20-60 交易日，周线粒度）：主线确认与否决的核心窗口，所有结论在此产生。
- W3 长窗（近 60-250 交易日，月线粒度）：判断产业趋势位置——趋势初段、中段，还是已演绎已久。

对每个候选方向依次回答：W1 谁在涨？→ W2 谁在持续吸金？→ W3 它走到哪一步了？

冷却规则（防单日冲动，强制适用）：仅在 W1 内首次爆发、此前 20 日涨幅榜从未出现的方向，无论当日多强，首日一律标「候选观察」；需在 W1 窗口内连续 2 个交易日以上保持强势（板块涨幅前列 + 有涨停跟随），且 D1/D2 至少各得 1 分，才允许升级为「候补」。冷却期内禁止写入 verdict=主线。

▍第三步 · 四维证据评分卡（对每个候选方向逐项打分，每维 0-2 分，标准如下）

D1 价格持续性
- 2 分：W2 窗口内跑赢沪深300 的天数占比 ≥60%，且板块指数位于 MA20 与 MA60 之上、MA20 > MA60
- 1 分：跑赢占比 40%-60%，或均线多头未完全形成
- 0 分：占比 <40%，或板块指数跌破 MA60
- 辅助特征：近 20 日中 ≥1/3 交易日进涨幅前 10 = 反复上榜（加分旁证）；单日脉冲后消失 = 直接 0 分
- 序列缺失时按第一步「◇ 降级」节执行：区间涨幅代理最高「中」

D2 资金持续性
- 2 分：W2 窗口主力资金累计净流入为正，且板块成交额占全市场比重趋势抬升
- 1 分：净流入为正但占比持平或回落
- 0 分：累计净流出
- 结构质量：缩量回调后放量再攻 = 健康（旁证加分）；天量滞涨 = 警惕（评分不超过 1）
- 板块 20 日资金序列缺失时按第一步「◇ 降级」节执行：近 5/10 日口径旁证，最高 1 分

D3 赚钱效应（情绪结构）
- 2 分：涨停梯队先锋—中军—跟风三层完整，且板块内存在 20 日涨幅 >50% 的标杆股
- 1 分：有涨停、有龙头，但梯队残缺（缺中军或跟风断层）
- 0 分：无持续涨停与赚钱效应
- 广度校验：板块内上涨家数占比过半为有效普涨；仅 1-2 只权重股拉指数 = 评分不超过 1

D4 逻辑驱动
- 2 分：政策驱动 / 产业趋势 / 业绩兑现至少占其一，能指出具体事件或数据，且近 2 周被新事件加强
- 1 分：有逻辑支撑但近 2 周无新增催化
- 0 分：纯资金博弈、一次性消息刺激、或逻辑已被证伪

▍第四步 · 主线确认标准（分数线判定，在 W2 窗口内执行）

先算总分（D1+D2+D3+D4，满分 8），再按分数线定档：
- 确认主线：总分 ≥6 且 D1+D2 ≥3（价格与资金必须双强），且不在冷却期；
- 候补主线：总分 4-5，或总分 ≥6 但 D1+D2 = 2（缺哪条注明），进入观察名单；
- 轮动题材：总分 ≤3，不纳入主线，报告中一句话带过。

对确认的主线做生命周期定位（判断依据：量能结构、龙头行为、调整后能否再创新高）：
启动期（首波上攻、梯队未完整）→ 发酵期（梯队完整、龙头新高）→ 高潮期（补涨扩散、成交占比见顶）→ 分歧期（龙头滞涨、跟风大面）→ 退潮期（亏钱效应、排名消失）。

**stage 字段只写单一标准词，五选一，禁止括号限定或箭头拼接。** 尚未跨越阶段、但已出现反向信号的，阶段维持原档，把信号写进 `stageNote`（如「高位分歧初现」）；确需表达「正在过渡」的，也写 stageNote（如「高潮期→分歧期过渡中」），stage 仍填当前所处档位。理由：stage 是枚举字段，混入限定语会让报告页的生命周期定位失效（曾出现「发酵期（高位分歧初现）」被误渲染为分歧期）。

▍第四步附 · 上期对账（附带上期台账时强制执行，未附带则跳过并在 dataGaps 登记）

1. environment 各项 prev 值优先引用上期台账同字段；与其他来源数字不一致时，注明「与上期台账口径差异」及以哪个为准；
2. 输出 meta 前，对照上期 meta 写一句差异说明（纳入 summary）：结论延续还是变化；
3. 距上期完整版不足 5 个交易日、且结论发生档位变化（确认主线 ↔ 候补观察 ↔ 无主线·轮动市）时，必须逐条列出推翻依据——每条依据必须是窗口级证据变化（资金转向、梯队瓦解、逻辑证伪），**单日情绪冲击不构成推翻依据，只能标注「分歧信号，待周末确认」**。

▍第五步 · 输出 JSON（严格遵循，供可视化报告页直接渲染）

输出分两部分，缺一不可：
① 一行人类可读结论：主线：__｜阶段：__｜置信度：__｜环境态：__
② 一个 JSON 代码块，内容为严格符合下述 Schema 的单个 JSON 对象；除这两部分外禁止输出任何其他正文。

字段规范（未获取的数据填 null 并写入 dataGaps；所有 value 字段必须带 source）：

字段内容格式约束（防长文本污染渲染）：
- source 统一紧凑格式「来源｜日期」（30 字内），多源对比、口径说明、计算细节一律写入 dataGaps，禁止塞进 source；
- volumeTrend 填短语（如「放量+1700亿」「连续3日缩量」），禁止段落式描述；
- maxConBoards.theme 只填题材名（如「机器人」），连板梯队细节写入 ladder 或对应 candidate.note。
```

## 四、轻量提示词 · 每日快检（整段复制，有昨日台账时一并粘贴）

```text
你是 A 股市场情绪与主线跟踪员。联网获取最近一个交易日收盘数据，输出 5 分钟快报 + JSON 台账。所有数字必须带 [来源｜日期]，取不到写「缺口」，禁止编造；盘中数据须标注「盘中」。

输入附带：用户可能在提示词末尾附上「昨日快报 JSON」。若附上，所有「较上日」对比与冷却期计数（第 N 日）以昨日台账同字段为准，与其他来源不一致时注明；若未附带，冷却期从第 1 日起算，并在 dataGaps 登记「无昨日台账，跨日判断（连续第 2 日 / 冷却计数）降级为当日口径」。

获取：① 今日涨停家数、跌停家数、最高连板及题材、炸板率；② 市场广度（上涨家数占比%）；③ 行业与概念板块涨幅前 5、跌幅前 3；④ 上周既定主线方向的今日表现（龙头是否新高、梯队是否完整、量能是否异常）；⑤ 大盘收盘位置（相对 MA20/MA60，限填「上方 / 下方 / 附近」；均线值无需单独搜索——用近 20/60 日收盘序列的收盘价算术平均自行计算，禁止凭年内跌幅等间接证据推断；取不到填 null）与量能。

▍输出（两部分，缺一不可）

① 快报（固定格式）：
# 主线日报 · [日期]
1. 情绪温度：[六选一：冰点/回暖/发酵/高潮/分歧/退潮]——涨停 __ 家（较上日 ±__）｜最高 __ 连板（题材：__）｜炸板率 __%｜广度 __%
2. 今日最强方向：__（属性：既有主线延续 / 高潮补涨 / 新候选）
3. 主线健康度：延续 / 分歧 / 退潮信号——一句依据（龙头是否新高、梯队是否完整、量能是否异常）
4. 切换预警：无 / 有（量化标准：新方向连续 2 日涨幅排名高于旧主线 且 涨停家数更多 且 有连板龙头；无昨日台账时写「无法判定」）
5. 环境态提示：广度跌破 35% 或升破 55% 时标「环境态或变，待周度确认」，否则写「无」
6. 一句话操作提示（对照当前环境态与信号权限）

② JSON 台账（与每日复盘模板 v2.0 口径一致的精简对象，逐日追加归档，供周度完整版作 W1 证据）：

{
  "date": "",
  "sentiment": {"limitUpCount": {"value": 0, "prev": 0, "source": ""}, "limitDownCount": {"value": 0, "source": ""}, "maxConBoards": {"value": 0, "theme": "", "source": ""}, "blastRate": {"value": 0, "source": ""}, "breadth": {"value": 0, "source": ""}, "phase": ""},
  "index": {"name": "", "vsMA20": "", "vsMA60": "", "volumeTrend": "", "source": ""},
  "strongest": {"name": "", "attr": ""},
  "mainline": {"name": "", "health": "", "evidence": ""},
  "switchAlert": "",
  "newCandidates": [{"name": "", "note": ""}],
  "statusUpdate": "",
  "dataGaps": [""],
  "sources": [""]
}

字段说明：sentiment.phase 为六选一周期标签；strongest 为今日最强方向 {name, attr}——attr 限「既有主线延续 / 高潮补涨 / 新候选」三选一，取不到填 null；mainline.health 为 延续/分歧/退潮信号 三选一（禁止组合填法）；switchAlert 无预警填 null，无昨日台账、无法执行切换判定时填「无法判定：无昨日台账」；newCandidates 的 note 写「冷却期第 N 日」；statusUpdate 写环境态阈值提示与对照周度台账的状态变化，无则填 null。

纪律：单日数据只更新状态，不推翻周度主线结论；新爆发方向一律适用冷却规则——首日只标「新候选 · 冷却期第 1 日」，连续 2 日强势后标「待周度四维评分」，禁止当日宣布切换主线。
```

## 五、报告生成提示词 · JSON → 苹果风 HTML（整段复制，与 JSON 一并发送）

> 使用方式：先按第三节跑完分析拿到 JSON → 把下面提示词 + JSON 一起粘贴给具备代码能力的 Agent → 得到一个双击即可打开的单文件 HTML 报告。
> 也可以直接走路径 A：把 JSON 导入本目录现成的 `market-mainline-report.html`，跳过本节。

```text
你是前端工程师兼视觉设计师。我将给你一份 A 股主线分析的结构化 JSON（Schema 见数据本身）。请生成一个单文件 HTML 报告，全部 CSS/JS 内联，双击即可在浏览器打开，不依赖构建工具。严格遵守以下设计与内容规范。

▍内容结构（自上而下，章节 id 与导航锚点一一对应）
1. Hero 结论区（黑色 #000000 画布）：报告日期、主线名称（大字）、阶段徽章、置信度徽章、环境态徽章、一句话结论摘要；徽章用胶囊几何，确认主线用 #0071e3 蓝，候备用中性灰，无主线用警示文案但不用红色系堆砌
2. 市场环境仪表盘：五个指标卡——涨停家数（含较上日增减）、最高连板（含题材）、炸板率、市场广度、指数状态（MA20/MA60 相对位置 + 量能）；每卡标注数据来源与日期
3. 候选方向评分表：表格或卡片列表展示全部 candidates，含四维评级（强/中/弱用色阶区分）、score 总分（用 0-8 的横向评分条可视化）、verdict、一句话证据；冷却期候选用「冷却中」标签降饱和呈现
4. 四维证据链：按 D1-D4 分四张卡片，每卡含标题、等级、要点列表（每条要点带来源标注）
5. 相对强度曲线：纯 SVG 折线图，主线板块 vs 沪深300 近 60 日累计涨幅；数据点 <4 个时降级为三点柱状快照图；完全缺失时显示「数据缺口」占位说明
6. 梯队金字塔：纯 SVG 三层金字塔（先锋/中军/跟风），标注个股名与一句话 note；某层为空时该层显示缺口样式
7. 失效警报：2-3 条 alerts，用左侧竖线引述样式，每条写清触发条件与应重估的对象
8. 体系联动卡：环境态、本周信号权限、板块共振名单（芯片式排布）
9. 数据缺口与来源：dataGaps 列表 + sources 去重列表，小字号灰字，透明度略低
10. 页脚：固定免责声明（市场有风险、仅供参考、不构成投资建议）

▍视觉规范（苹果风，严格执行）
- 色彩基底：黑 #000000 / 浅灰 #f5f5f7 / 白 #ffffff 三色章节交替；主文本 #1d1d1f，次要文本 #6e6e73；行动与强调蓝 #0071e3，深场景链接蓝 #2997ff；边框 #d2d2d7
- 蓝色纪律：蓝色只用于关键结论、强调数字与交互元素，不大面积铺色
- 字体：font-family: -apple-system, "SF Pro Display", "SF Pro Text", "Helvetica Neue", "Inter", "PingFang SC", "Microsoft YaHei", sans-serif；Hero 标题 48-56px/600，章节标题 28-40px/600，正文 17px/400，辅助说明 12-14px
- 几何：卡片圆角 18px，徽章与按钮用胶囊（border-radius: 980px），指标卡白底细边框、克制阴影（rgba(0,0,0,0.08) 以内）
- 布局：最大宽容器约 980-1100px 居中，章节上下留白 80-120px，信息密度由 Hero 到数据区渐进
- 图表：全部纯 SVG 手绘风格，坐标轴与网格线用 #d2d2d7 细线，数据系列主线 #0071e3、基准线 #86868b 虚线
- 动效：以纯 CSS 为主——章节淡入上移（必要时可用 IntersectionObserver 添加 class，但样式动画全部写在 CSS）、数字滚动、卡片 hover 轻微上浮（translateY(-2px) + 阴影加深）、评分条宽度展开动画；禁止引入重型动画库
- 导航：顶部固定半透明毛玻璃导航（backdrop-filter: blur(20px)），含各章节锚点链接，滚动时当前章节高亮（scroll-spy，JS 允许用于此交互）

▍数据完整性规则
- JSON 中为 null 或缺失的字段：对应区块显示「数据缺口」占位，禁止编造数字填补
- 每个数字渲染时保留 JSON 中的 source 标注（小字灰显）
- dataGaps 非空时，在 Hero 区结论摘要下方加一条低调的「本次分析存在数据降级」提示条

▍交付前自查
文件单文件可双击打开；导航锚点与章节 id 全部匹配；SVG 标签开闭配对；宣称的图表数与实际渲染数一致；所有数字可回溯到 JSON 字段；控制台无报错。
```

## 六、人工复核检查单（判断 AI 输出质量）

| # | 检查项 | 合格标准 |
|---|---|---|
| 1 | 数据真实性抽查 | 任选 3 个数字对照行情软件，误差合理、来源日期齐全 |
| 2 | 结论-证据一致性 | 结论里的每个方向都能在 JSON 的 candidates / evidence 中找到对应证据 |
| 3 | 窗口纪律 | 报告结论引用的是 20-60 日窗口证据，而非单日涨跌幅 |
| 4 | 评分卡自洽 | 抽 1 个候选方向：d1-d4 评级按评分标准能复算出相同分数，且 强=2/中=1/弱=0 加总等于 score |
| 5 | 冷却规则执行 | 首次爆发的新方向没有被直接标为主线/候补，note 中有冷却期标注 |
| 6 | 情绪数据核对 | 涨停家数/连板高度与开盘啦或同花顺人工对一次（AI 最易错项） |
| 7 | 「无主线」勇气 | 弱市中 AI 是否敢于给出「轮动市、无主线」结论 |
| 8 | verdict 联动校验 | selfCheck 中算式加总全部等于 score；verdict 与候选分数档位匹配（有 ≥4 分候补却写「无主线」= 不合格） |
| 9 | 上期对账 | prev 值与上期台账一致或注明差异；结论变档时附带了窗口级推翻依据而非单日情绪 |
| 10 | 均线口径核对 | vsMA20/vsMA60 与行情软件均线位置一致（自算值抽查复算）；dataGaps 含「推断」表述而对应字段非 null = 不合格（推断必须 null + dataGaps 旁证） |
| 11 | 序列自算与资金口径 | 抽 1 个板块依收盘序列复算跑赢占比/均线；资金净流入各源口径已核对、无跨口径混合或自创区间值；relativeStrength 非「近 2 日两点」冒充快照；ladder 个股当日行情逐只有来源 |

## 七、局限与注意

- AI 联网取数的实时性与准确性无法完全保证，**涨停/连板等情绪数据是最易出错的部分**，人工抽查（检查单第 6 项）不可省；
- 东方财富与同花顺的概念板块分类存在口径差异，跨来源对比时以同一来源为准；
- 环境态广度阈值（35% / 55%）、评分卡分数线（≥6 / 4-5 / ≤3）、20 日涨幅 50% 等参数为**经验参数**（与主报告三态表口径一致），调整权限在月度校准层，须基于不少于 20 笔有效样本、每次只调一个并记录理由；
- 评分卡把定性判断变成了可复核的分数，但**打分依据本身仍来自 AI 对窗口数据的解读**——分数降低的是随意性，不是不确定性；
- 冷却规则会付出「晚一天确认」的代价，这是用一点滞后换单日脉冲防线的有意取舍，不要因踏空首日而绕过它；
- 主线判断本质是概率游戏：模板的价值在于强制证据结构化、防止单日冲动，而不能消除不确定性；
- 建议按周度节奏使用完整版，**高频跑完整版反而会放大噪音、诱发过度交易**——日度交给轻量版（无操作日）或每日复盘模板（有操作日）；有/无操作日的 JSON 可分别归档为 `daily-ledger.json` 和 `daily-fast.json`，两者字段兼容，周度完整版都可作为 W1 证据输入；
- AI 输出的 JSON 字段不全时，报告页（路径 A/B 均是）会对缺失项显示「数据缺口」并整体降级呈现——这是设计内行为，勿因页面留白而质疑模板；
- relativeStrength 逐日序列：具备代码执行能力时走接口取序列可完整自算；纯网页搜索多数情况只能取到区间快照，序列不足 4 点时相对强度图自动降级为快照图，不影响其余板块渲染；
- v3.0/v3.1 的 JSON 与 v2.0 报告页完全兼容：旧页忽略新增 score / selfCheck 字段，新报告生成提示词会把 score 渲染为评分条；
- selfCheck 是 AI 的自证记录，能降低算错概率但不能根除——人工复核时抽 1 个候选重算一遍，仍是最后一道防线；
- 上期对账机制依赖用户附带上期 JSON，忘记附带时 AI 只能登记缺口跳过——把上期文件放进同一个文件夹、养成一并粘贴的习惯，是这个机制生效的前提。
